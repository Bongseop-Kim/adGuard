# eval: 자체 적격평가 세트

개발 전에 미리 만들어 두는 **예상 정량평가 문제지 + 정답표 + 통과 기준**이다.
탐지기는 이 세트를 전부 통과해야 완성으로 본다. 근거 자료는 `docs/research/02~05`에 있다.

## 폴더 구조

```
eval/
├── README.md              ← 이 문서 (규칙·ID·통과 기준)
├── scenarios/
│   ├── S0-empty/          ← 광고 없는 사이트
│   ├── S1-baseline/       ← 모집요강 예시 재현형
│   ├── S2-realistic/      ← 실전 공공 누리집형
│   └── S3-stress/         ← 시간 측정용 대형 사이트
├── blind/                 ← 블라인드 세트 (개발 중 열람 금지)
└── scorer/                ← 채점기 (todo/02에서 구현)
```

시나리오 폴더 하나의 구성:

```
SX-name/
├── spec.md        ← 사이트 구조, 페이지 목록, 각 정답·미끼의 의도
├── answer.json    ← 정답표 (아래 형식)
├── serve.py       ← 사이트 실행 (Python 표준 라이브러리만, Windows·macOS 공용)
├── site/          ← 본 도메인 파일
└── site_ext/      ← 다른 도메인 iframe용 파일 (필요할 때)
```

## 서버 규칙

- `python serve.py`로 실행하고, Python 3.10 이상 표준 라이브러리만 쓴다. 외부 패키지는 쓰지 않는다.
- 본 도메인은 `http://127.0.0.1:<포트>`, 다른 도메인은 `http://localhost:<포트+1>`이다. 호스트명이 다르면 다른 출처로 취급된다.
- POST 게시판, 리다이렉트, 느린 응답, 인코딩처럼 정적 파일로 안 되는 동작만 `serve.py`에 코드로 넣는다.

| 시나리오 | 본 도메인 | 다른 도메인 |
|---|---|---|
| S0 | 8100 | 8101 |
| S1 | 8110 | 8111 |
| S2 | 8120 | 8121 |
| S3 | 8130 | 8131 |
| blind | 8190 | 8191 |

## 테스트용 광고 문구 방침

테스트에 필요한 것은 실제 광고가 아니라 **탐지기가 보는 신호**(범주 키워드와 패턴)다.

- 범주 키워드는 그대로 쓴다: 카지노, 토토, 바카라, 슬롯, 먹튀, 첫충, 성인, 대포통장, 법인통장, 통장 임대, 환전, 불법 대출 등
- 연락처와 식별자는 전부 가짜 형식으로 쓴다
  - 텔레그램: `@test_` 접두 (예: `@test_promo_01`)
  - 도메인: 예약 도메인 `.test`, `.example`
  - 전화: `010-0000-` 번호
  - 가입 코드: `TEST`로 시작
- 마약·불법 대출처럼 위험한 범주는 범주 키워드만 쓰고, 구체적인 판매·거래 방법은 쓰지 않는다
- 문구는 짧게 쓴다. 한 건에 범주 키워드 1~2개와 가짜 연락처 1개면 충분하다

## 정답표 형식 (`answer.json`)

```json
{
  "scenario": "S1",
  "entry_url": "http://127.0.0.1:8110/",
  "answers": [
    {
      "id": "a_001",
      "url": "http://127.0.0.1:8110/board/view?id=1024",
      "location": "div.notice-board > span.visually-hidden",
      "technique": "JAMO",
      "evidence_text": "ㅋㅏㅈㅣㄴㅗ ...",
      "covers": ["J01", "P02"],
      "note": "의도 설명"
    }
  ],
  "decoys": [
    {
      "url": "http://127.0.0.1:8110/",
      "location": "a.skip",
      "covers": ["D01"],
      "note": "본문 바로가기 (정상 접근성 텍스트)"
    }
  ],
  "extra": [
    { "url": "...", "location": "...", "extra_finding": "VISIBLE_AD", "covers": ["D07"], "note": "result_extra.json에만 나와야 함" }
  ]
}
```

- `answers`: `result.json`에 반드시 나와야 하는 항목이다. 판정은 url + location + technique이 모두 일치해야 정답이다.
- `decoys`: `result.json`에 나오면 오탐이다.
- `extra`: `result_extra.json`에만 나와야 하는 항목이다. `result.json`에 나오면 오탐이다.
- `location`은 모집요강 규칙으로 쓴다: 태그+클래스, ` > `, `:nth-of-type()`, 속성값 큰따옴표, iframe은 `iframe[src="절대URL"] >>> `.
- 정답 location은 **렌더링 DOM과 원본 HTML 양쪽에서 정확히 1개 요소**를 가리켜야 한다.

## 채점 규칙 (모집요강 12쪽 그대로)

- url·location·technique이 모두 일치해야 정답이다.
- url 비교: 끝 `/`, http/https, `#` 이하는 무시한다. 쿼리 값이 다르면 다른 페이지이고, 순서만 다르면 같은 페이지다.
- location 비교: 문자열이 아니라 **같은 요소를 가리키는지**로 판정한다. 2개 이상을 가리키면 오답이다.
- url·location·technique이 같은 항목이 여러 번 나오면 1건으로 합친다.
- 스키마를 지키지 않은 항목은 오답이다. 파일 전체를 파싱할 수 없으면 0점이다.

## 블라인드 규칙

- `blind/`는 이 README와 `docs/research/`만 보고 별도 에이전트가 만든다.
- 탐지기를 개발하는 동안 `blind/` 안의 파일은 **열어 보지 않는다**. 채점기 실행 결과(점수와 놓친 건수)만 본다.
- 블라인드에서 놓친 건은 수정하기 전에, 원인이 일반 규칙의 누락인지 먼저 확인하고 기록한다. 그 문제 하나만 맞추는 수정은 하지 않는다.
