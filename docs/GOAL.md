# adGuard 최종 목표

## 목적

**점검할 웹사이트의 URL 1개를 입력하면, 그 사이트 각 영역(하위 페이지, 게시글, 댓글, iframe 내부)에 게시되거나 숨겨진 불법광고(도박·성인물 등)를 자동으로 찾아내고, 유형을 분류하고, 위치를 식별해서 사용자에게 화면과 결과 파일(`result.json`)로 알려주는 Windows 도구를 만든다.**

> 원문(붙임1): "사용자가 점검 대상 웹사이트 URL을 입력하면 해당 웹사이트 각 영역에 게시되거나 숨겨진 불법광고를 자동으로 찾아내고 유형 및 위치 등을 확인할 수 있는 도구 개발"

## 최종 목표

「공공 웹사이트 불법광고 탐지 도구 개발 공모전」(행정안전부 주최, NIA 주관)에서 **대상(행정안전부장관상)**을 받는다.

1. 적격평가 100점 → 본심사 후보 15팀 안에 든다
2. 본심사 100점 → 대상 (동점이면 정량평가, 창의성, 실무 활용성 순으로 비교)

|---|---|---|

## 목표 체크리스트

### 1. 필수 탐지 4종 (적격평가 대상)
- [ ] HOMOGLYPH: 키릴·전각 문자, 숫자, 그 밖에 비슷하게 생긴 문자를 섞어 필터링을 피하는 기법
- [ ] JAMO: 음절을 자모 단위로 쪼개 키워드 매칭을 피하는 기법 (예: `ㅋㅏㅈㅣㄴㅗ`)
- [ ] TRANSPARENT: 배경과 같은 글자색, `opacity:0`, `color:transparent` 등으로 시각적으로 숨기는 기법
- [ ] OFFSCREEN: `font-size` 0~1px, `position:absolute; left:-9999px`, `display:none` 처리

### 2. 탐색 범위
- [ ] 입력 URL에서 시작해 하위 페이지, 게시글, 댓글 영역까지 탐색
- [ ] 페이지에 삽입된 iframe 내부 요소까지 탐색
- [ ] 쿼리 값이 다르면 다른 페이지로 취급 (`?id=1024`와 `?id=1180`은 다름, 쿼리 순서만 다르면 같음)

### 3. 결과 파일 `result.json` (필수)
- [ ] 파일명 `result.json`, UTF-8(BOM 없음), JSON
- [ ] 최상위 키는 `meta`, `findings` 두 개뿐
- [ ] `meta.topic`: `"TOPIC"` 고정
- [ ] `meta.entry_url`: 입력받은 진입 URL
- [ ] `meta.started_at`, `meta.finished_at`: ISO 8601, 예 `2026-10-22T10:00:00+09:00`
- [ ] `meta.elapsed_sec`: 숫자(초)
- [ ] `meta.tool_version`: 문자열 (선택)
- [ ] `findings`: 전체 사이트의 검출을 담은 **배열 1개** (페이지별로 나누지 않음). 검출이 없으면 `[]`
- [ ] findings 항목 필수 필드: `id`(파일 안에서 중복 없음, 예 `f_001`), `url`(전체 URL), `is_violation`(boolean), `location`, `evidence_text`(정규화 전 원문), `technique`
- [ ] `technique`는 `HOMOGLYPH`, `JAMO`, `TRANSPARENT`, `OFFSCREEN` 중 **하나만** (2개 이상 나열하거나 배열로 쓰면 안 됨)
- [ ] 검출 1건 = (url + location + technique) 조합 1개
- [ ] 한 요소에 기법 2개 이상 → 기법마다 1건씩 따로 (url·location은 같고 코드만 다름)
- [ ] 한 요소 안에 같은 기법 문자열 여러 개 → 1건으로 묶음
- [ ] 실행 파일이 있는 폴더에 생성 (다른 곳에 만들면 사용설명서 첫 장에 경로 명시)

### 4. `location` 작성 규칙
- [ ] CSS 선택자를 원칙으로 함
- [ ] 태그명과 클래스를 함께 쓰고, 상위 요소부터 ` > `(앞뒤 공백 1칸)로 연결 (예: `div.notice-board > span.visually-hidden`)
- [ ] 클래스가 없는 요소는 `tr:nth-of-type(7)`처럼 순서로 지정
- [ ] 속성값은 큰따옴표로 표기
- [ ] iframe 내부는 `iframe[src="주소"] >>> 선택자` (`>>>` 앞뒤 공백 1칸, 중첩되면 `>>>` 반복, 상대 경로 src는 절대 주소로)
- [ ] 선택자가 **요소 2개 이상을 가리키면 오답**. 표기 방식이 달라도 같은 요소를 정확히 가리키면 정답

### 5. 추가 탐지 결과 `result_extra.json` (선택, 본심사 자료)
- [ ] 4종 외 탐지 유형을 구현하면 별도 파일로 생성 (`meta` + `findings`)
- [ ] `technique: "ETC"` 고정, 유형 이름은 `extra_finding`에 기재

### 6. 사용자 화면 (필수, 실무 활용성 20점)
- [ ] 탐지 결과를 사용자에게 안내하는 화면 제공 (결과 파일과 별도로)
- [ ] URL 입력 → **"탐지 시작"** → 진행 상황 → **"탐지 완료"** 흐름 (검출 시간을 이 구간으로 잼)
- [ ] 결과마다 탐지 원인·근거(원문, 위치, 기법 설명) 제공
- [ ] 업무에 쓸 수 있는 안내·관리 기능 (예: 내보내기, 이력, 조치 상태)

### 7. 실행 환경
- [ ] Windows 11에서 실행되는 실행 파일
- [ ] GPU가 없는 일반 PC, CPU·RAM만으로 동작
- [ ] 상용 AI API를 쓰는 경우:
  - [ ] API KEY를 소스코드에 넣지 않고(하드코딩 금지) 별도 `.env`에서 실행 시점에 읽음
  - [ ] 주최 측 키로 교체만 하면 재빌드·재컴파일 없이 정상 동작
  - [ ] 주최 측이 키를 발급할 수 있는 서비스 사용 (예: OpenAI, Google Cloud Vision)
  - [ ] 사용설명서에 API 서비스명·모델명·환경변수명 명시
- [ ] 직접 운영하는 외부 서버가 있으면 심사 기간(10.26~11.4) 내내 접속 가능하게 관리
