## 핵심 결론 (우선순위 변경 제안)

1. **S-4의 "양방향 제어 문자를 지운다"는 틀렸다.** RLO(U+202E)를 지우면 `노지카`가 남는다. 화면에는 `카지노`로 보인다. 같은 효과를 문자 없이 CSS `unicode-bidi:bidi-override; direction:rtl`, flex `row-reverse`, `order`로도 낼 수 있다(피싱 메일 실사례 Inky 2019). **글자별 화면 좌표로 "사람이 읽는 순서"를 복원**하면 다섯 변형이 한 번에 잡힌다 [실험]. 새 유형 `VISUAL_REORDER`로 독립시키고 S등급으로 올린다. 창의성 시연용으로 가장 좋다(구현 반나절, 통제 환경 100% 재현, 기존 도구가 못 함).
2. **S-3 클로킹은 "봇 UA"만으로는 부족하다.** 실제 캠페인은 **모바일 UA + 검색 유입 Referer**일 때만 광고·리다이렉트를 보여 주고(인도 2026, Sucuri 2023, polyfill.io 2024), **관리자 쿠키가 있으면 숨는다**(polyfill.io). 그리고 데스크톱에는 404를 준다. 프로필을 `일반 / Googlebot / Yeti / 모바일+네이버·구글 Referer` 4개로 늘리고, 상태 코드 차이(봇 200, 사람 404)도 비교한다. 오탐 함정은 두 가지다. Cloudflare 같은 WAF가 가짜 Googlebot을 막는 경우, 그리고 페이지 자체가 바뀌는 경우다. 같은 프로필로 두 번 받아서 **자연 변동량**을 빼야 한다(Cloak of Visibility).
3. **S-2 도메인 탈취는 `<a href>`만 보면 안 된다. `<script src>`·`<iframe src>`까지 봐야 한다.** polyfill.io(2024, 11만 사이트)는 주인이 바뀐 외부 스크립트가 모바일 사용자만 스포츠 도박 사이트로 보냈다. 외부 스크립트 도메인 목록과 알려진 탈취 도메인 대조는 **외부망이 막혀도 동작**한다.
4. **"행동 후 노출·지연 삽입"은 실제로 가장 흔한 클라이언트 클로킹이다.** CrawlPhish(IEEE S&P 2021) 기준 사용자 상호작용형이 57~65%, 타이밍형이 17~20%다. 우리 대기(DOM 안정 후 최대 3초)를 넘기는 지연이나 클릭 후 리다이렉트는 놓친다. 상위 N페이지에만 **합성 클릭·스크롤·마우스 이동 + 이동 요청 가로채기** 2차 패스를 둔다. A등급 신규 후보다.
5. **QR 코드 속 URL은 9일 안에 "동작"을 보여 줄 수 있다.** `zxing-cpp` 휠은 1MB이고 의존성이 없다. 페이지 이미지를 캔버스 회색조 바이트로 넘겨 `t.me/...`를 해독하는 것까지 확인했다 [실험]. 함정이 있다. 브라우저 `BarcodeDetector`는 **macOS·ChromeOS 전용이라 Windows에서 안 된다**(MDN BCD). C-9(OCR)보다 싸고 확실하므로 B로 올린다.
6. **동일·유사 문구 다수 게시(봇 스팸 캠페인)는 사전에 없는 신종 표현도 잡는다.** 근거로 Gao 외(IMC 2010)의 "같은 URL 또는 유사 문구 → 캠페인 묶음, 분산성·버스트성으로 판정"과 Meta 2026의 "정상처럼 보이는 단어 조합 + 댓글 반복"이 있다. A-7·R15(IOC 묶음)를 **문구 유사도 묶음**으로 넓힌다.
7. **S-4에 한글 채움 문자(U+3164, U+115F, U+1160, U+FFA0)를 넣는다.** 유니코드 `Default_Ignorable_Code_Point`에 들어 있지만 Python `unicodedata`에는 이 속성이 없으므로 목록을 직접 넣어야 한다. 렌더링은 폰트에 따라 다르다(macOS 기본 폰트에서는 보임 [실험], Windows 맑은 고딕은 확인 필요).
8. **제외할 것:** 폰트 글리프 치환은 실사례가 있지만(Proofpoint 2019) 화면 OCR 없이는 일반 탐지가 안 되므로 C로 둔다. canvas 텍스트는 DOM에 없어서 OCR 말고는 방법이 없으므로 C로 둔다. 백스페이스(U+0008) "삭제" 공격은 Chromium에서 글자를 지우지 않아 효과가 없으므로 제외한다 [실험]. `::before` content는 싸지만 실사례를 찾지 못해 B로 두고, 시연용으로만 쓴다.

## A. 기존 S-1~S-4 보강: 함정·오탐·실제 탐지기 특징

### S-1 내부 검색 반사형(ISAP)

**발견** — Zhang 외 USENIX Sec 2024 본문 확인 [확인]
- 논문의 "ISAP Website Finder" 판정은 두 조건이다. ① 검색어가 **결과 URL**에 들어감(GET) ② 검색어가 **페이지 `<title>`**에 들어감. 본문 반사는 일부러 무시한다("We ignore keyword occurrences in other parts of the webpage"). 검색 엔진이 title을 가장 중시하기 때문이다.
- 검색창 찾기: schema.org `SearchAction` 선언에서 검색 URL을 먼저 뽑는다. 없으면 class·id에 "search"가 들어간 버튼을 클릭해 나오는 `<input>`/`<textarea>`를 고르고, `hidden, submit, button, checkbox, radio, email, password, image, tel, reset, file, color, range, date…` 유형은 뺀다(Table 2). 캐너리 검색어는 `isap-test` 같은 무해한 문자열이고, 사이트당 평균 5초 걸렸다.
- 성능: 오탐 1.68%, 미탐 11.58%. **오탐의 주원인은 자체 검색이 아니라 외부 검색엔진(`site:` 구문)을 부르는 사이트**였다. 미탐은 대부분 HTTP 응답 오류였다.
- **정부 사이트는 title이 기관명으로 고정된 경우가 많아 위험이 낮다**는 관찰이 있다. 교육기관(EDU)은 24.59%가 취약했다.
- URL 쪽 탐지 특징: 검색어 길이 5자 미만은 제외한다. 검색어는 바뀌어도 **홍보 대상(도메인·텔레그램 ID)은 고정**이므로 공출현 빈도로 뽑는다. 불용어로 `Facebook`, `Telegram` 같은 흔한 단어와 사이트 자체 도메인을 둔다.
- 권고 조치: ① POST로 검색하고, URL·title에 검색어를 넣지 않는다 ② 결과가 없는 검색은 `noindex` 처리한다.

**우리 계획 시사점**
- S-1 (b) 진단의 판정 기준을 논문과 맞춘다. **"URL 반사 + title 반사 + 색인 허용(noindex 없음)"이 셋 다 성립할 때만 '노출 위험'**으로 표시한다. 본문에만 반사되는 경우는 '참고'로 낮춘다. 이렇게 하면 기획서에 "USENIX 2024와 같은 기준"이라고 쓸 수 있다.
- 검색 폼의 `action`이 외부 검색엔진이면(다음·구글 `site:`) 진단에서 제외한다. 논문의 오탐 원인을 그대로 막는 장치다.
- 조치 안내 문구에 논문 권고 두 줄(POST·title 제외, 결과 0건 noindex)을 넣는다.
- **함정 [가설]:** ISAP URL은 원래 **다른 사이트(유포처)**에 뿌려지므로, 대상 사이트만 크롤하면 ISAP URL을 만나지 못할 수 있다. 사이트 안에서 이를 만나는 경로는 '인기·최근 검색어' 위젯, 검색 결과 페이지끼리의 링크, sitemap 정도다. 위젯 경로를 확인한 자료는 찾지 못했다. 출제 사이트가 ISAP를 넣는다면 위젯이나 직접 링크 형태일 가능성이 높으므로, `?q=`·`?keyword=`·`?searchWrd=` 같은 검색 파라미터가 붙은 URL은 크롤 우선순위를 올린다.

**통제 환경 시연**: 쉽다. 테스트 사이트 검색 페이지가 GET + title 반사를 하면 바로 재현된다. **난이도**: 낮음.

### S-2 외부 링크 도메인 탈취

**발견**
- **polyfill.io (Sansec 2024-06-25) [확인]:** 주인이 바뀐 CDN 스크립트가 ① 모바일 UA에서만 동작하고(Windows·Mac 플랫폼이면 건너뜀) ② `admin_id`·`adminlevels` 쿠키가 있으면 꺼지며 ③ 시간대별로 10~20% 확률로만 ④ 분석 스크립트가 있으면 2초 늦게 실행되어 **스포츠 도박 사이트로 리다이렉트**했다. 영향은 11만 사이트 이상이다.
- **Parking Sensors (Vissers 외 NDSS 2015) [확인, PDF 본문]:** 파킹 도메인 판별 특징은 링크 안 텍스트 비율, 링크가 아닌 글자 수, 제3자 광고, 프레임 구성, 리다이렉트 체인이다(HTML 11, HAR 5, frame 4, domain 1). 성능은 TPR 97.9%, FPR 0.5%. **파킹 페이지는 방문의 7%±0.9%에서 다른 도메인으로 리다이렉트**되고, 그중 일부는 성인물·사기·악성코드로 갔다.
- Domain-Z (Lever 외 IEEE S&P 2016) [요약만]: 만료 뒤 악의적으로 재등록된 도메인 수십만 개를 측정했다(residual trust).
- 러시아 대학 옛 도메인이 카지노 포털로 바뀐 사례 (casinobeats 2026-05-07) [요약만].

**시사점**
- **수집 대상 확장**: `<a href>`에 더해 `<script src>`, `<iframe src>`, `<link rel=stylesheet>`, `<img>` 외부 도메인을 "외부 의존 목록"으로 모은다. 스크립트 도메인 탈취는 링크보다 피해가 크다(모든 방문자에게 실행된다).
- **외부망 없이도 되는 오프라인 검사**: 알려진 탈취·악성 스크립트 도메인 목록(확인된 것은 `polyfill.io`)과 대조한다. 같은 운영자의 다른 CDN 도메인(bootcss·bootcdn·staticfile 등으로 알려짐)은 **이번에 확인하지 못했다**. 구현 때 Sansec 원문 갱신분에서 목록을 확인한다.
- **판정 함정**: 파킹 페이지는 가끔만 리다이렉트하므로 한 번 요청한 결과로 '정상'이라 단정하지 않는다. 대신 Parking Sensors 특징(본문 대부분이 링크, 링크가 아닌 텍스트가 매우 적음, "domain for sale" 문구)으로 **'소유권 상실 의심'**을 따로 표시한다. 광고 판정이 나지 않아도 관리자에게는 조치 대상이다.
- 외부 응답이 도박으로 판정되면 위반으로 본다. 파킹 판정만 나오면 '주의' 등급이다.

**통제 환경 시연**: 외부망이 막혀 있으면 실제 외부 요청은 실패한다. 시연은 ① 테스트 사이트 안에 "탈취된 척하는" 두 번째 호스트(포트 다르게)를 두고 ② 오프라인 목록 대조(polyfill.io 스크립트 태그)로 한다. **난이도**: 중간(현 계획과 같음, 수집 대상만 늘어남).

### S-3 검색봇 클로킹

**발견**
- **Cloak of Visibility (Invernizzi 외 IEEE S&P 2016) [확인, PDF 본문]**
  - 프로필 11개(Googlebot·Chrome 데스크톱·Chrome Android × Referer 유무 × 클릭 유무 × 네트워크)를 쓴다. 각 프로필로 **3번씩** 받아 페이지 자체의 변동량을 잰다. 프로필 간 차이를 이 자연 변동량으로 나눈 값이 특징이 된다.
  - 가장 강한 단일 특징은 **출처가 다른 도메인으로 가는 JS 리다이렉트**다(클로킹 41.8% 대 정상 0.62%). 그 밖에 텍스트 simhash, 스크린샷, 요청 트리, 요소 Jaccard, 토픽 유사도를 쓴다.
  - 클로커는 **봇에게만 404·파킹·"차단된 사이트"를 주거나**, 반대로 사람에게만 바꾼다. 여러 홉을 거치며 쿠키로 '방문→클릭' 순서를 강제하기도 한다.
  - 오탐 원인 3가지: ① 받는 사이에 콘텐츠가 바뀜 ② 연결 오류·40X ③ **Cloudflare "checking your browser" 중간 페이지**. 대책은 "모든 요청을 짧은 시간 안에 끝내는 것"이다.
  - 추천 프로필 일부만 써도 대부분 잡힌다고 밝힌다("only a few of these profiles are necessary").
- **Sucuri 2023-09-05 [확인]:** 모바일만 노리는 수법이 있다. 서버 쪽 PHP는 UA에 `mobile`이 있을 때만 스크립트를 삽입하고, 클라이언트 JS는 모바일 UA 목록으로 검사한 뒤 **`onclick`일 때만** 이동시킨다. 단축 URL은 모바일 UA가 아니면 404를 준다. 2023년 1~8월 2.4만 사이트에서 발견됐다.
- **Sucuri 2026-01-08 [확인]:** UA로 Googlebot·Bingbot·Baiduspider를 가려 "Situs Toto" 도박 스팸을 보여 준다. 원격 파일을 가져와 출력한 뒤 `exit`하고, 출력 전에 **무작위로 잠깐 멈춘다**.
- **인도 2026 (MediaNama) [확인]:** Googlebot에는 키워드 도배 페이지, **구글 검색에서 들어온 모바일 사용자에게는 도박 앱 리다이렉트**, 관리자·데스크톱에게는 정상 페이지나 404를 준다.
- **Trend Micro BadIIS 2025-02-07 [확인]:** UA 키워드는 `360, baidu, bing, coccoc, daum, google, naver, sogou, yisou`, Referer는 `baidu.com, bing.com, daum.net, google, naver.com, so.com, sogou.com, sm.cn`이다. **피해 국가에 한국이 포함**된다. 별도의 "Injector 모드"는 일반 방문자 응답에 XOR(0x03)로 난독화한 JS를 끼워 `document.write`로 외부 스크립트를 부른다. 이 모드는 렌더링 기반인 우리 엔진이 그대로 잡는다.
- **hunt.io gov.br (2025-06 발견) [확인]:** 크롤러에는 정부 템플릿을 복제한 키워드 도배 페이지(템플릿 자리표시자 `{{keyword}}`·`{{outurl}}`가 남아 있음)를 주고, 사람에게는 도박·APK·텔레그램 안내로 리다이렉트한다. URL 63만 개 규모다.
- **Cloudflare 가짜 봇 규칙 [확인]:** UA가 봇인데 역DNS·IP 검증에 실패하면 '가짜 봇'으로 표시한다. 2026-02-10에 기본 동작이 Block에서 Disabled로 바뀌었지만[요약만], 직접 켠 사이트에서는 **우리 Googlebot 요청이 막혀 '차이'가 생긴다.**

**시사점**
- 프로필을 `일반 데스크톱 / Googlebot / Yeti / Daum / 모바일 Chrome + Referer(google·naver 검색)`로 확정한다. 모바일+Referer는 인도·Sucuri·polyfill 세 사례가 공통으로 노린 조합이다.
- **비교 항목**: 본문 텍스트 + **상태 코드 + 최종 URL(리다이렉트 체인) + `<meta refresh>`·JS 리다이렉트 목적지 + `<title>`/meta**. 봇에게만 200이고 사람에게 404인 경우도 신호로 본다(Google web.dev: 해킹 페이지가 404로 숨는다).
- **오탐 통제**:
  - 일반 프로필을 두 번 받아 자연 변동(시각·배너·CSRF 토큰)을 뺀다.
  - 봇 응답이 403/429/챌린지 페이지(`cf-chl`, "checking your browser")면 '판정 불가'로 둔다. 클로킹으로 보지 않는다.
  - 기존 규칙대로 봇 쪽에 광고 패턴이 있을 때만 위반으로 본다.
- **우리 도구는 늘 깨끗한 프로필(쿠키 없음)로 접속한다**는 점을 차별화 문구로 쓴다. polyfill(관리자 쿠키 회피)과 성심당몰 2024(보안뉴스: 한 번 띄운 뒤 쿠키로 다시 안 띄움 [요약만])처럼 **관리자 브라우저로는 안 보이는** 공격이 있다.
- 탐지 결과에 `{{keyword}}` 같은 남은 템플릿 자리표시자를 별도 신호로 둔다. 싸고 오탐이 거의 없다.
- IP·GeoIP 기반 클로킹은 못 잡는다는 한계 표기는 유지한다.

**통제 환경 시연**: 테스트 서버에서 UA·Referer 분기는 10줄이면 재현된다. 외부망은 필요 없다. **난이도**: 낮음(프로필 1개와 비교 항목 추가).

### S-4 보이지 않는 문자·주석·속성

**발견**
- Bad Characters (IEEE S&P 2022) [확인, 초록]: 보이지 않는 문자, 닮은꼴, **재배열(reordering)**, 삭제(deletion)의 4가지 섭동 계열을 다룬다.
- Trojan Source (USENIX Sec 2023, CVE-2021-42574) [요약만]: 양방향 제어 문자로 저장 순서와 화면 순서를 다르게 만든다.
- 유니코드 `DerivedCoreProperties.txt` [확인]: `Default_Ignorable_Code_Point`에 `00AD, 034F, 115F..1160, 180B..180F, 200B..200F, 202A..202E, 2060..206F, 3164, FE00..FE0F, FEFF, FFA0, E0000..E0FFF` 등이 들어 있다.
- [실험] Chromium 렌더링 결과:
  - U+0008(백스페이스)은 앞 글자를 지우지 않는다(`카A\b지노` → 화면 `카A지노`). **삭제 계열은 웹에서 효과가 없다.**
  - U+007F는 빈칸처럼 보인다.
  - U+3164·U+115F는 macOS 기본 폰트에서 **눈에 보이는 글리프로 그려졌다.** 폰트마다 다르다.
  - U+00AD·U+200B·U+2066/2069는 보이지 않는다.

**시사점**
- 보이지 않는 문자 목록을 `Default_Ignorable_Code_Point` 전체로 잡는다. Python 표준 라이브러리에 이 속성이 없으므로 범위 표를 코드에 넣는다(20줄).
- **양방향 제어 문자는 지우지 말고 재배열로 처리한다**(아래 신규 1).
- 정상 문서 오탐 요인: 에디터 붙여넣기의 U+FEFF·U+200B, 이모지 ZWJ·변형 선택자(FE0F), 아랍어·히브리어의 RLM. 모두 "제거 후 키워드가 될 때만" 규칙으로 걸러진다.
- 한글 채움 문자는 Windows 맑은 고딕에서 빈칸으로 그려지는지 todo/07(실기 확인) 때 같이 본다. **확인 필요**.

### 신규 1. 시각 순서 뒤집기 `VISUAL_REORDER` (추천: S로 신설)

**발견**
- **Inky 2019 [확인, PDF]:** 실제 피싱 메일(2019-07)이 `unicode-bidi: bidi-override; DIRECTION: rtl`로 HTML에는 `563 eciffO`를 넣고 화면에는 `Office 365`를 보여 메일 보안 게이트웨이의 패턴 매칭을 피했다. KnowBe4 2020-04-09 재보도 [확인].
- **Trustwave SpiderLabs 2014-09-05 [확인]:** U+202E(RLO)로 `remotsuc raeD`를 `Dear customer`로 보이게 해 스팸 필터를 우회했다.
- MITRE ATT&CK T1036.002 (RLO 파일명 위장) [요약만].
- **[실험] Chromium (scratchpad/exp/t.html):**

| 변형 | DOM `innerText` | 화면 | 글자별 Range 좌표로 복원 |
|---|---|---|---|
| CSS `unicode-bidi:bidi-override; direction:rtl` + `노지카` | `노지카` | 카지노 | `카지노` |
| `&#x202E;노지카&#x202C;` | RLO 포함 `노지카` | 카지노 | `카지노` |
| flex `row-reverse` + `<span>노</span><span>지</span><span>카</span>` | `노\n지\n카` | 카지노 | `카지노` |
| flex `order:3/2/1` | `노\n지\n카` | 카지노 | `카지노` |
| `writing-mode: vertical-rl` `바카라` | `바카라` | 세로 바카라 | `바카라` (위→아래 정렬) |

  복원 방법: 텍스트 노드의 글자마다 `Range.getBoundingClientRect()`를 구하고, 같은 줄(top)끼리 묶어 left 순으로 정렬한다. 이 결과에 4종 키워드 매처를 다시 돌린다.

**시사점**
- 06 §4 S-4의 "양방향 제어 문자를 지운 뒤 키워드"는 **오히려 틀린 답을 낸다**(`노지카`). 재배열을 별도 유형으로 분리한다.
- 비용 통제: 모든 글자의 좌표를 재지 않는다. 다음 조건의 요소에서만 잰다. ① 계산된 `unicode-bidi`가 `*-override`이거나 `direction:rtl` ② 텍스트에 U+202A~202E·U+2066~2069가 있음 ③ flex·grid 부모가 `*-reverse`이거나 자식에 `order`가 있음 ④ `writing-mode`가 가로가 아님.
- 오탐 통제: 실제 아랍어·히브리어 문자(스크립트 R/AL)가 들어 있으면 건너뛴다. 복원한 문자열이 원문과 다르고 **복원 결과에만 광고 키워드가 있을 때만** 보고한다.
- 4종과의 관계: 숨김이 아니고 문자 치환도 아니다. 그래서 `result.json` 4종에는 넣지 않고 `result_extra.json` ETC로 보낸다. 같은 요소가 다른 4종 기법도 쓰면 그 기법은 따로 1건으로 낸다.
- 기획서 문구 후보: "DOM이 아니라 **사람이 보는 글자 순서**로 읽는다."

**통제 환경 시연**: 완전히 재현된다(정적 HTML 한 줄). **난이도**: 낮음(반나절). **기존 도구와의 차별**: Sucuri·Search Console·금칙어 필터 모두 원문 순서로 매칭한다.

### 신규 3. 행동 후 노출·지연 삽입 `INTERACTION_TRIGGERED` (추천: A)

**발견**
- **CrawlPhish (Zhang 외 IEEE S&P 2021) [확인, 저자 사이트 본문]:** 피싱 사이트 112,005개 중 35,067개가 클라이언트 쪽 클로킹을 썼다. 유형별 비율(APWG / 공개 데이터셋)은 다음과 같다.
  - 사용자 상호작용 57.60% / 64.55%: 팝업 알림 17.19 / 25.89, 클릭 통과 22.11 / 22.82, 마우스 감지 16.53 / 6.86
  - 타이밍 19.80% / 16.90%
  - Referrer 6.69% / 9.03%, User-Agent 3.98% / 3.58%, Cookie 12.53% / 9.87%
  - 상호작용형 비율은 2018년 40.11%에서 2019년 61.23%로 늘었다.
- Sucuri 2023: 모바일 리다이렉트가 `onclick`에서만 실행된다 [확인].
- polyfill: 분석 스크립트가 있으면 2초 지연한다 [확인].
- Sucuri 2017 "Play One"·2018 [확인]: 스팸 div를 **JS가 로드 후 숨긴다**. `'dis'+'play'`, `'n'+'one'`, `214*102+105` 같은 숫자 ID로 정적 분석을 피한다. 이건 렌더링 후 판정하는 우리 방식이 이미 잡는다(최종 상태 기준).
- Cloak of Visibility: 랜딩 후 몇 초 기다렸다가 **가장 큰 요소를 클릭**하고, 이동이 없으면 다음 요소를 클릭한다 [확인].

**시사점**
- 상위 N페이지(진입 URL·메인·게시판 목록)에만 2차 패스를 둔다.
  - `mousemove` → `scroll`(끝까지) → 본문 가장 큰 요소에 합성 `click`을 보낸다.
  - `page.route`로 문서 이동 요청과 `popup`을 가로채 목적지만 기록하고 중단(abort)한다. 이미 03에서 쓰는 패턴이다.
  - 클릭 전후 DOM 텍스트의 차이에 광고 패턴이 생기거나, 목적지 도메인이 광고로 판정되면 보고한다.
- 지연 삽입은 3초 대기를 늘리는 대신 **타이머 가속**을 쓴다. `add_init_script`로 `setTimeout`·`setInterval`의 1초 넘는 지연을 1/10로 줄이는 방식이다. **[가설]** 이 방법의 실제 효과를 검증한 문헌은 찾지 못했다. 캐러셀 같은 정상 동작이 빨라져 화면이 바뀔 수 있으므로 2차 패스에서만 쓴다.
- 결과 위치(location)는 "클릭 후 나타난 요소" 또는 "클릭한 요소"로 하고, 근거에 "합성 클릭 후 노출"을 적는다.

**통제 환경 시연**: 된다. `setTimeout(…, 8000)` 삽입이나 `document.onclick=()=>location=…`을 재현할 수 있다. **난이도**: 중간(1~1.5일). 4종 검출 시간을 해치지 않도록 1차 결과를 먼저 저장한 뒤 실행한다.

### 신규 4. QR 코드 속 URL `QR_CODE_URL` (추천: C-9에서 분리해 B, 여유 있으면 A)

**발견**
- 중앙일보 2024-05-06 (다음 뉴스) [확인]: 서울 가리봉동·부천 심곡본동의 불법 도박장 전단·주차 표지판 QR이 위챗·온라인 원격 도박장으로 연결됐다. 오프라인 사례이고 웹 게시판 사례는 찾지 못했다.
- 더우인(Douyin)의 "QR 코드로 자동 검수를 우회한다" 발언은 sigma.world 기사로만 확인됐다 [요약만, 원문 403].
- **[실험]** `zxing-cpp` 3.1.1(Windows cp312 휠 1,003,677바이트, 의존성 없음)로 처리했다. 페이지의 `<img>`를 캔버스에 그리고 `getImageData`를 회색조 바이트로 만들어 `memoryview(...).cast('B', shape=[h,w])`로 넘겼더니 `https://t.me/toto_kakao_777`이 해독됐다. numpy·PIL은 필요 없다.
- **함정 [확인, MDN browser-compat-data]:** Chromium `BarcodeDetector`는 "Supported on ChromeOS and macOS only"다. **Windows 평가 PC에서는 동작하지 않는다.** 맥에서 개발할 때만 되고 실기에서 실패하는 전형적인 함정이다.
- 추가 함정 [가설]: 다른 출처의 이미지는 캔버스를 오염시켜 `getImageData`가 실패한다. 이때는 Python에서 바이트를 받아 → 페이지에 base64로 넘기고 → `createImageBitmap(blob)`으로 그리거나, 요소 스크린샷을 쓴다. 구현할 때 확인한다.

**시사점**
- 해독된 URL·텔레그램 ID는 A-7 IOC와 R15 캠페인 묶음으로 바로 이어진다. "이미지 속 연락처까지 추출"을 실무 활용성 근거로 쓴다.
- 비용 상한: 본문·게시판 첨부 이미지 중 가로·세로 80px 이상이고 정사각형에 가까운 것만, 페이지당 10장 이하로 처리한다.
- OCR(C-9)과 달리 해독 결과가 확정적이라 오탐이 거의 없다. URL을 광고 분류기로 판정한 경우에만 위반으로 본다.

**통제 환경 시연**: 된다(외부망 불필요). **난이도**: 낮음~중간(0.5~1일, exe 용량 +1MB). 런타임 의존성 "playwright 하나" 원칙을 깨므로 todo/01 결정에 예외로 적어야 한다.

### 신규 5. 동일·유사 문구 다수 게시(봇 캠페인) `SPAM_CAMPAIGN_CLUSTER` (추천: A, R15 확장)

**발견**
- Gao 외 "Detecting and Characterizing Social Spam Campaigns" (IMC 2010): 초록에서 1억 8,700만 게시물 중 악성 약 20만 건, 계정 5.7만 개, 97% 이상이 탈취 계정임을 확인했다 [확인, 초록]. 방법(같은 목적 URL 또는 매우 유사한 문구를 간선으로 잇고, 분산성·버스트성으로 판정)은 서베이(arXiv 1504.03342)의 설명이다 [요약만].
- Meta 2026-06-30 (VOI, 인도네시아 Komdigi 공동 회견) [확인]: 도박 홍보자가 "정상처럼 보이는 코드·단어·키워드 조합"과 **댓글란**으로 검수를 피한다고 밝혔다. Meta는 2025년 한 해 도박 관련 콘텐츠 약 6,100만 건을 삭제했다.

**시사점**
- 사전에 없는 신조어나 은어 광고도 **같은 문구가 여러 게시물에 반복**되면 잡힌다. 키워드 사전 기반인 4종의 빈틈을 메운다(창의성 포인트).
- 방법: 게시물·댓글 본문을 정규화(4종 엔진 결과 재사용) → 문자 5-gram MinHash(표준 라이브러리 `hashlib`만으로 가능) → Jaccard 0.8 이상을 묶는다.
- 판정 조건: 묶음이 **서로 다른 게시물 3건 이상**이고, (연락처·URL IOC가 있거나 광고 분류기 점수가 임계값 이상).
- 오탐 통제: 템플릿 영역(헤더·푸터·공지 고정글)은 제외하고 사용자 작성 영역에만 적용한다. 같은 작성자의 정상 반복(정기 공지)은 IOC가 없으면 제외한다.

**통제 환경 시연**: 테스트 게시판에 같은 문구 글 5개를 두면 된다. **난이도**: 낮음~중간(0.5일). 크롤 범위가 제한되면 묶음이 작아져 효과가 줄 수 있다.

### 신규 6. CSS 생성 콘텐츠 `CSS_GENERATED_TEXT` (추천: B, 시연용)

**발견**
- [실험] `#a::before{content:"카지노 첫충 30%"}`는 화면에 보이지만 `innerText`, Playwright `inner_text()`, `get_by_text('카지노')`(0건) **어디에도 나오지 않는다**. `getComputedStyle(el,'::before').content`로만 얻는다.
- 실제 스팸·SEO 사례는 **찾지 못했다**. 스크레이퍼 회피용 상용 난독화 도구 홍보 글만 있었다 [요약만]. Talos 2025 CSS 남용 글에도 의사 요소 언급은 없다 [확인].
- 검색엔진은 CSS 생성 텍스트를 색인하지 않으므로[가설] SEO 목적에는 쓸모가 없다. 쓰인다면 게시판 금칙어 필터 우회용이다.

**시사점**
- 02 §1에 이미 "content 문자열도 검사"가 있다. 추가할 것은 두 가지다. ① `content: attr(data-x)`도 계산값으로 해석되는지 확인 ② location은 의사 요소가 아니라 **호스트 요소**를 가리킨다.
- 실사례가 약하므로 기획서에는 "렌더링 기반이라 덤으로 잡는다" 정도로만 쓴다.

**통제 환경 시연**: 된다. **난이도**: 매우 낮음(1시간).

### 신규 7. 단축 URL (A-7에 흡수, 오프라인 규칙 추가)

**발견**
- Maggi 외 (WWW 2013) [확인, 초록]: 단축 서비스 622개, 단축 URL 약 2,500만 개를 측정했다. 서비스들의 대책은 "ineffective and trivial to bypass"였다.
- Sucuri 2023 [확인]: 가짜 단축 도메인 100개 이상. **모바일 UA가 아니면 404**를 주고, 모바일이면 302를 준다.
- Zhang 외 NDSS 2025 "Misdirection of Trust" [요약만]: 기업 전용 단축 서비스 악용.

**시사점**
- 외부망이 막혀도 동작하도록 **단축 도메인 목록 대조**(bit.ly, tinyurl.com, is.gd, t.ly, cutt.ly, han.gl, me2.do, vo.la, url.kr, naver.me 등)만으로 IOC에 "단축 URL"로 표시한다. 국내 단축 도메인 목록은 구현 때 확인한다.
- 해석할 때는 **`HEAD`·리다이렉트 비추적으로 `Location` 헤더만** 읽는다(최종 사이트에 접속하지 않음). **모바일 UA로 한 번 더** 요청한다(Sucuri 사례).

**통제 환경 시연**: 목록 대조는 된다. 해석은 외부망이 있어야 한다. **난이도**: 낮음.

### 신규 8. SVG·canvas 텍스트

- [실험] SVG `<text>`는 `textContent`와 `body.innerText`에 나오고 글자 좌표도 잡힌다. 다만 **요소 자체의 `innerText`는 `null`**이다. 탐지 JS가 `el.innerText`를 쓰면 SVG 안 광고를 놓친다. TreeWalker로 텍스트 노드를 순회하면 문제없다.
- [실험] canvas `fillText('바카라')`는 DOM에 흔적이 전혀 없다. OCR 말고는 방법이 없다.
- 실사례: SVG 피싱은 2025~2026년에 급증했지만(Microsoft 2026-02 기준 약 120만 건 등 [요약만]) 메일 첨부 얘기이고, 웹 게시판 광고 사례는 못 찾았다.
- **시사점**: SVG는 "텍스트 노드 순회" 구현 규칙으로 04에 한 줄 추가(신규 유형 아님). canvas는 C-9(OCR)와 묶어 '확장 계획'으로 둔다.

### 신규 9. 웹폰트 글리프 치환 (추천: C, 기획서 '확장 계획'만)

**발견**
- Proofpoint (BleepingComputer 2019-01-04) [확인]: 미국 대형 은행 피싱 키트(2018-05~06)가 base64로 넣은 woff/woff2 폰트를 치환 암호로 썼다. 소스에는 뒤섞인 글자가 있고 화면에는 정상 문장이 보인다. "the intended text will be shown in the browser, but will not exist on the page". 로고는 SVG로 그렸다.

**판단**
- 탐지는 ① 화면 OCR과 DOM 텍스트 비교, 또는 ② 폰트 `cmap`·글리프 이름 분석(예: U+B178에 `uniCE74` 글리프가 매핑됨)으로 해야 한다. ②는 글리프 이름이 `cid12345`처럼 의미 없는 폰트에서는 실패한다. fontTools 의존성도 필요하다.
- 한글은 치환 대상 글리프가 많아 폰트가 커진다. 하지만 광고 문구 몇 글자만 담은 서브셋이면 수 KB로 가능하다[가설]. 출제자가 넣을 수는 있지만 4종 범위 밖이라 가능성은 낮다고 본다.
- **결론**: 9일 안에 "제대로 동작"을 보장하기 어렵다. 인정받지 못하는 유형이 될 위험이 있으므로 기획서의 한계·확장 계획에만 적는다. 다만 신호 하나는 싸다. **`data:` URL 웹폰트가 본문 일부에만 적용됨**을 '참고'로 표시하는 정도는 가능하다(판정 아님).
