# 정확도 판정 규칙: 4종 기법 판정 알고리즘과 location 생성

- 작성: 2026-10-14
- 담당 평가 항목: 적격평가 **정답 추출 정확도 (35점)**. 정밀도(오탐, 기법 오분류)와 필드 정확도(url·location·technique 일치, 스키마)를 다룬다.
- 방법: 공식 명세(WCAG 2.2, UTS #39, MDN), 오픈소스 코드(axe-core, @medv/finder, KOTOX, 스팸체 생성기)를 읽고, 판정 로직은 **로컬 Chrome 155 headless에서 48개 케이스로 직접 돌려 확인**했다. "직접 확인"은 이 검증을 뜻한다.

## 핵심 결론

1. **은닉 판정은 CSS 속성을 하나씩 대조하지 말고 "글자가 실제로 그려진 박스"로 판단한다.** 텍스트 노드의 `Range.getClientRects()`, 조상 클리핑 교차, 누적 opacity, 조상 순회 배경색과 WCAG 대비율을 쓰면 48개 케이스가 모두 맞았다(직접 확인). 배경 이미지나 그라데이션 위의 글자는 **글자를 투명하게 바꾼 스크린샷과 비교**해 판정한다.
2. **기법 코드는 원인 속성의 계열로 정한다.** 색·투명도 계열(color, opacity, filter:opacity, visibility, text-fill)은 TRANSPARENT, 배치·크기·렌더링 계열(display, font-size, 좌표, transform, clip, overflow, text-indent, letter-spacing)은 OFFSCREEN이다. 한 요소에 두 계열이 모두 걸려 있으면 2건을 낸다.
3. **HOMOGLYPH와 JAMO는 `skeleton(NFKC(x))` 하나로 매칭하고, 기법 코드는 매칭 구간의 원문 글자 종류로 정한다.** NFKC만으로도 `ㅋㅏㅈㅣㄴㅗ`는 `카지노`로 합쳐지지만 받침은 잘못 붙는다(`ㄱㅏㅁ`→`가ᄆ`). 전각 하이픈은 skeleton만으로는 풀리지 않는다(직접 확인). 그래서 두 정규화를 모두 쓰고, 한글과 비슷한 한자·가나 표는 confusables + 스팸체 생성기 + KOTOX 사전(MIT)으로 만든다.
4. **출력 조건은 "기법 신호 AND 광고성"이다.** 모집요강 예시 2(`ｍｅｇａ－ＢＥＴ 첫충 30% 지급`)는 변형된 부분이 사전에 없는 브랜드명이다. 따라서 HOMOGLYPH는 "변형된 글자가 키워드 안에 있어야 한다"가 아니라, **같은 요소 안에 변형 토큰과 광고 신호가 함께 있으면** 출력해야 한다.
5. **location은 근거 텍스트를 가진 가장 안쪽 요소로 하고, 렌더링된 DOM과 원본 HTML 모두에서 고유한지 검증한다.** 브라우저는 `<tbody>`를 자동으로 넣지만 html.parser와 lxml은 넣지 않는다(직접 확인). 이 때문에 `table > tr`는 한쪽 DOM에서만 맞는다. 자동으로 들어간 tbody 구간은 자손 결합자(공백)로 건너뛴다.

## 0. 채점 구조에서 나오는 출력 결정 규칙

모집요강 6·12쪽 내용: 정확도 = "전체 탐지 건수 대비 정탐 비율", url·location·technique 3개가 모두 맞아야 정탐, 스키마 미준수 항목은 오답, 같은 항목 중복은 1건으로 통합, location이 2곳 이상을 가리키면 오답.

채점 공식이 다음과 같다고 **가정**하면(공식은 비공개), 애매한 후보를 출력할지 정하는 기준을 계산할 수 있다.
- 검출 개수 점수 = 45·H/T, 정확도 점수 = 35·H/N (H 정탐 수, T 정답 수, N 제출 수, 현재 정밀도 P = H/N)
- 정탐 확률이 q인 후보 1건을 추가할 때의 점수 변화는 Δ ≈ 45q/T + 35(q − P)/N 이다. N ≈ T이면 **q > 0.44·P일 때 이득**이고, P=0.9이면 **q > 약 0.4**다.
- location 후보가 둘(예: 텍스트를 가진 자식과 숨김 스타일이 걸린 부모)이고 첫째 후보가 맞을 확률이 p일 때, 둘 다 내는 쪽이 이득인 조건은 p < 1 − 0.44·P이다. P=0.9이면 **p < 약 0.6**이다.
- 따라서 **확신이 약 60% 미만인 양자택일은 둘 다 내고, 정탐 확률이 약 40% 미만인 후보는 버린다.** 이 원칙은 아래 경계 사례 판단에 그대로 적용한다. 단, 정밀도가 이미 낮으면(P≈0.6) 기준이 q > 0.26으로 내려가므로, 우리 도구의 정밀도를 자체 채점기로 측정한 뒤 다시 계산한다.

## 1. 공통 판정 파이프라인

```
for frame in page.frames (중첩 iframe 포함):
  textNodes = 공백이 아닌 텍스트 노드 전부 (script/style/template/noscript 내부 제외)
  for 요소 E = 텍스트 노드의 부모 요소 (같은 부모의 텍스트 노드는 하나로 묶음):
     hide  = hidden_signals(E)        # §2, §3 → {OFFSCREEN?, TRANSPARENT?}
     obf   = obfuscation_signals(E)   # §5, §6 → {HOMOGLYPH?, JAMO?}
     if not (hide or obf): continue
     text_norm = deobfuscate(E의 텍스트)   # NFKC + 자모 조합 + skeleton + 한국어 닮은꼴 표
     if ad_score(text_norm, raw) < 기준: continue     # §7
     for tech in (hide ∪ obf): emit(url, location(E), tech, evidence=원문)
  dedup (url 정규화, location, technique)
```

- 후보 단위는 **텍스트를 직접 가진 요소**다. 모집요강 예시 4건(`span.visually-hidden`, `td.title > a`, `p.desc > span`, `div.wrap > span.hidden-link`)이 모두 말단의 텍스트 요소다.
- 숨김 신호는 요소 자신뿐 아니라 **조상에서 온 것**(조상 display:none, 조상 opacity:0, 조상 overflow 클리핑)도 포함한다. location은 텍스트를 가진 요소로 쓴다. 숨김 루트가 따로 있을 때의 처리는 §4.3을 따른다.

## 2. OFFSCREEN (화면 밖 은닉)

### 2.1 판정 알고리즘

```
offscreen_signals(E):                      # E = 텍스트를 직접 가진 요소
  cs = getComputedStyle(E)
  1) 렌더링 안 됨:  !E.checkVisibility()   → display:none(자신·조상), hidden 속성,
                    content-visibility:hidden, 닫힌 <details>
  2) 글자 크기:     parseFloat(cs.fontSize) <= 1        (모집요강 "font-size:0~1px")
  rects = E의 직속 텍스트 노드마다 Range.selectNodeContents(t).getClientRects()
  3) 글자 박스 붕괴: max(h) <= 1 or Σw <= 1                       (scale(0), letter-spacing:-1em)
                    max(h) < 3 or Σw/글자수 < 1.5                 (2px 글꼴, letter-spacing 큰 음수)
  4) 문서 밖:       모든 rect가 right+scrollX <= 0 or bottom+scrollY <= 0
                    or left+scrollX >= max(scrollWidth, innerWidth)
                    (left:-9999px, text-indent:-9999px, translateX(-9999px), margin-left:-9999px, top:-9999px)
                    ※ 아래쪽·오른쪽으로 멀리 있는 것은 스크롤하면 보이므로 숨김이 아니다
  5) 클리핑:        clipBox = 자신과 조상의 clip/clip-path/overflow 영역의 교집합
                    - clip: rect()는 position absolute/fixed일 때만 적용
                    - clip-path: inset(x)는 각 변을 x만큼 줄임 (50% 이상이면 영역 0)
                    - overflow != visible인 조상의 padding box. 단, E가 fixed면 조상 overflow 무시,
                      E가 absolute이고 그 조상이 static이면 무시 (axe-core 규칙과 같음)
                    - overflow auto/scroll이면 scrollWidth/Height까지 영역을 넓힘 (스크롤하면 보임)
                    - E 자신의 overflow도 자기 텍스트를 자른다 (line-height:0;height:0;overflow:hidden)
                    visible = Σ area(rect ∩ clipBox) / Σ area(rect)
                    visH = max(rect ∩ clipBox의 높이 / rect 높이)
                    visible < 0.05 or visH < 0.35  → 잘려서 안 보임
  OFFSCREEN = 1~5 중 하나라도 참
```

근거와 차용한 부분:
- `checkVisibility()`는 기본값으로 **박스가 없는 경우(display:none, display:contents)와 content-visibility:hidden만** 검사한다. 화면 밖 위치, 가림, 글자 크기, clip, 색은 검사하지 않는다. opacity와 visibility는 옵션(`opacityProperty`, `visibilityProperty`)을 켜야 검사한다. — [MDN checkVisibility](https://developer.mozilla.org/en-US/docs/Web/API/Element/checkVisibility)
- 5)의 clip 정규식, clip-path `inset ≥ 50%`, overflow 조상의 absolute·fixed 예외, "조상 박스가 2px 미만이면 숨김"은 axe-core `visibility-methods.js`의 `clipHidden`, `overflowHidden`과 같다. 4)의 "왼쪽·위쪽 음수면 숨김, 아래쪽은 스크롤 가능하면 보임"은 axe-core `is-offscreen.js`와 같다. — [axe-core visibility-methods.js](https://github.com/dequelabs/axe-core/blob/develop/lib/commons/dom/visibility-methods.js), [is-offscreen.js](https://github.com/dequelabs/axe-core/blob/develop/lib/commons/dom/is-offscreen.js) (MPL-2.0. 코드를 복사하지 말고 규칙만 차용한다)
- axe-core와 다른 점: axe는 요소 박스(`getBoundingClientRect`)를 보지만, 우리는 **텍스트 노드의 rect**를 본다. `text-indent:-9999px`는 요소 박스는 화면 안에 두고 글자만 밖으로 밀어낸다. 그래서 요소 박스를 보면 놓친다(직접 확인: 케이스 07·08이 요소 박스로는 화면 안이고, 텍스트 rect로는 음수 좌표였다).

### 2.3 오탐 방지 규칙

| 상황 | 규칙 | 근거 |
|---|---|---|
| 접근성 숨김 텍스트(sr-only, blind, sound_only, "본문 바로가기") | 숨김 신호는 그대로 두고 **광고성 점수로만 거른다.** 클래스 이름 화이트리스트는 쓰지 않는다 | 모집요강 예시 정답이 `span.visually-hidden`. 행안부 누리집 한 페이지에서 716건 측정(01 문서) |
| 접힌 메뉴, 닫힌 탭·아코디언·모달 | 위와 같음. display:none 신호는 유지 | 정상 UI |
| 말줄임 처리된 게시판 제목 | 클리핑 기준을 "보이는 비율 < 0.05 또는 보이는 높이 < 35%"로 둔다. 가로로만 잘린 것은 숨김이 아니다 | 직접 확인(케이스 46: 0.40) |
| 스크롤 상자 | overflow auto/scroll은 scrollWidth·scrollHeight까지 보이는 영역으로 친다 | 직접 확인(케이스 47) |
| 페이지 아래쪽, 오른쪽 | 숨김이 아니다 | axe `is-offscreen` |
| `<marquee>`, 자동 슬라이드(캐러셀), CSS 애니메이션 | 측정 시점에 화면 밖일 수 있다. `cs.animationName != none`이거나 transition이 있거나 marquee 안에 있으면 **500ms 뒤 다시 측정**해서 위치가 바뀌면 숨김이 아니라고 본다 | 오래된 공공 누리집에 marquee 공지가 흔하다 |
| 반응형 숨김(모바일 메뉴가 데스크톱에서 display:none) | 뷰포트를 고정한다(1920×1080 권장). 광고성으로 거른다 | 출제자 정답은 데스크톱 기준일 가능성이 높다 |
| `<script>`, `<style>`, `<template>`, `<noscript>` 안의 문자열 | 텍스트 후보에서 뺀다. 필요하면 result_extra.json으로 보낸다 | axe `nativelyHidden`. 이 요소들은 "요소의 텍스트"가 아니다 |

### 2.4 경계 사례 판단

| 사례 | 판단 | 근거 |
|---|---|---|
| `visibility:hidden` | **TRANSPARENT** | 박스와 자리는 남고 그려지지만 않는다. opacity:0과 같은 "제자리 투명" 계열이다. axe도 visibility를 opacity와 별도로 "보이지 않음"으로 다룬다. OFFSCREEN으로 볼 여지도 있지만 위 계열 기준으로 TRANSPARENT로 정한다(§11) |
| `clip`, `clip-path`, 크기 0 + overflow, `max-height:0` | OFFSCREEN | 그려지는 영역이 0으로 잘린다. 크기와 배치 계열이다 |
| `text-indent:-9999px`, `margin` 음수, `transform: translate` | OFFSCREEN | 모집요강 예시 `left:-9999px`와 같은 "좌표를 화면 밖으로" 계열이다 |
| `letter-spacing` 큰 음수, `transform: scale(0)` | OFFSCREEN | 모집요강 예시 `font-size:0~1px`와 같은 "크기 축소" 계열이다 |
| `font-size:2~3px` | OFFSCREEN (광고성이 있을 때) | 모집요강은 0~1px만 명시한다. 2px는 사람이 읽을 수 없으므로 q가 0.4를 넘는다고 본다 |
| 다른 요소로 덮음(z-index 오버레이) | result.json에는 **내지 않는다.** result_extra.json에 ETC "OCCLUDED"로 낸다 | 4종 정의의 예시에 없다. elementFromPoint로 탐지는 된다(직접 확인: 케이스 27). q가 0.4 미만이라고 판단 |

## 3. TRANSPARENT (투명 텍스트)

### 3.1 판정 알고리즘

```
transparent_signals(E):        # 렌더링 여부와 관계없이 계산한다 (display:none 안이라도 색 속성은 판정)
  cs = getComputedStyle(E)
  1) cs.visibility in (hidden, collapse)                         → TRANSPARENT
  2) op = Π(조상 포함 opacity × filter:opacity()) ; op < 0.1     → TRANSPARENT
  3) fill = cs.webkitTextFillColor || cs.color
     fill.alpha < 0.1 and text-shadow 없음 and text-stroke 없음 → TRANSPARENT
  4) bg = effective_background(E)
     fg = blend(fill × op, bg)      # 반투명 글자색과 opacity를 배경 위에 합성
     cr = WCAG_contrast(fg, bg)
     bg가 확정되고 cr < 1.25 and shadow/stroke 없음              → TRANSPARENT
     bg가 불확정(배경 이미지·그라데이션·겹친 요소)이고 광고성 후보면 → 스크린샷 차분(§3.3)

effective_background(E):
  for n in E, E.parent, ... , html:
     if n.backgroundImage != none: return 불확정
     c = n.backgroundColor ; if c.alpha > 0: layers.push(c) ; if c.alpha == 1: break
  위에서 아래로 합성, 마지막에 흰색(#fff) 페이지 배경과 합성
```

- **WCAG 대비율**: L = 0.2126R + 0.7152G + 0.0722B, 각 채널은 c ≤ 0.04045이면 c/12.92, 아니면 ((c+0.055)/1.055)^2.4. 대비율 = (L1+0.05)/(L2+0.05). 2021년 5월 전에는 임계값이 0.03928이었으나 0.04045로 바뀌었다. — [WCAG 2.2 relative luminance](https://www.w3.org/TR/WCAG22/#dfn-relative-luminance)
- 배경 합성 순서(아래에서 위로 합성하고, 마지막에 흰색 페이지 배경), 배경 이미지를 만나면 판정 불가(`bgImage`, `bgGradient`)로 두는 것, 텍스트 rect를 다 덮지 못하는 배경 요소는 판정 불가로 두는 것은 axe-core `get-background-color.js`를 따른다. axe는 `elementsFromPoint`로 텍스트 위치에 쌓인 요소 스택을 구해서 배경을 계산한다(`get-background-stack.js`). absolute로 뒤에 깔린 형제 박스까지 잡으려면 이 방식이 필요하다. — [axe get-background-color.js](https://github.com/dequelabs/axe-core/blob/develop/lib/commons/color/get-background-color.js), [get-background-stack.js](https://github.com/dequelabs/axe-core/blob/develop/lib/commons/color/get-background-stack.js)
- 글자색은 `-webkit-text-stroke` → `-webkit-text-fill-color`(없으면 `color`) → `text-shadow` 순으로 쌓아서 계산한다. 글자가 투명해도 그림자나 외곽선이 있으면 보인다. — [axe get-foreground-color.js](https://github.com/dequelabs/axe-core/blob/develop/lib/commons/color/get-foreground-color.js)

### 3.2 임계값 1.25의 근거

| 글자색(흰 배경) | 대비율 | 판단 |
|---|---|---|
| #fff, #fefefe | 1.00, 1.01 | 투명 (직접 확인) |
| #fafafa / #f5f5f5 / #eeeeee | 1.04 / 1.09 / 1.16 | 투명 |
| #e5e5e5 | 1.26 | 경계 |
| #dddddd | 1.36 | 보임 (흐린 안내문, 미끼. 직접 확인) |
| #cccccc / #999999 | 1.61 / 2.85 | 보임 (WCAG AA 기준은 4.5, 큰 글씨 3.0) |
| 검정 글자 + opacity 0.05 / 0.1 / 0.2 | 1.12 / 1.25 / 1.61 | 0.1 이하만 투명 |

- 1.25는 opacity 0.1의 검정 글자와 같은 수준이다. 그래서 "opacity < 0.1"과 "대비율 < 1.25" 두 기준이 일관된다.
- 디자인으로 쓰는 흐린 회색(#ccc~#ddd, 1.36~1.61)은 사람이 읽을 수 있으므로 잡지 않는다. WCAG 기준값(4.5/3.0)은 "읽기 어려움" 기준이지 "안 보임" 기준이 아니므로 쓰지 않는다.

### 3.3 판정이 불확정일 때: 스크린샷 차분 (직접 확인)

배경이 그라데이션·이미지이거나 다른 요소와 겹쳐서 계산으로 배경색을 확정할 수 없으면, **같은 영역을 두 번 찍어 비교한다.**
1. `E.screenshot()`을 찍는다 (Playwright의 locator.screenshot, 애니메이션 정지 옵션 사용).
2. E에 `color:transparent!important; -webkit-text-fill-color:transparent!important; text-shadow:none!important`를 임시로 넣고 다시 찍는다.
3. 두 이미지에서 채널 차이가 24를 넘는 픽셀이 글자 면적의 1% 미만이면 글자가 보이지 않는 것이다 → TRANSPARENT. 그다음 스타일을 원래대로 되돌린다.

직접 확인: 흰색→흰색 그라데이션 위의 흰 글자는 두 PNG가 **바이트 단위까지 같았다**. 흰색→#eee 그라데이션 위의 #333 글자는 두 PNG가 달랐다. 이 방법은 mix-blend-mode, 겹침, 배경 이미지를 모두 처리한다. 다만 비용이 크므로 **광고성을 통과한 후보에만** 쓴다.

### 4.1 기법 코드 결정표

| 원인 속성(자신 또는 조상) | 코드 |
|---|---|
| color = 배경, color alpha 0, `-webkit-text-fill-color: transparent`, opacity, `filter: opacity()`, visibility:hidden | TRANSPARENT |
| display:none, hidden 속성, content-visibility, 닫힌 details, font-size ≤ 1px(2px 포함), 음수 좌표(left, top, margin, text-indent, translate), clip, clip-path, 크기 0 + overflow, letter-spacing 음수, scale(0) | OFFSCREEN |
| 전각·키릴·그리스·수학 영숫자·원문자, 한글과 닮은 한자·가나·기호, leet 숫자 | HOMOGLYPH |
| 호환 자모·첫가끝 자모·반각 자모로 음절 분해(구분자 삽입 포함) | JAMO |

### 4.2 중첩 출력 규칙

- 모집요강 10쪽: 같은 요소에 기법이 2개 이상 걸리면 기법마다 1건씩 출력한다. 같은 요소 안에 같은 기법의 문자열이 여러 개 있으면 1건으로 묶는다.
- **숨김 계열(OFFSCREEN/TRANSPARENT)은 서로 독립적으로 판정한다.** 예: opacity:0 + left:-9999px → 2건 (직접 확인: 케이스 39).
- **같은 계열 안의 여러 신호는 1건이다.** 예: sr-only는 1px, clip, overflow가 모두 OFFSCREEN이므로 1건이다.
- **숨김과 변형이 겹치면 각각 낸다.** 예: 숨긴 span 안의 `ｍｅｇａ－ＢＥＴ` → OFFSCREEN 1건 + HOMOGLYPH 1건, location은 같다.
- **자모 분해와 닮은꼴이 한 문자열에 있으면 둘 다 낸다.** 예: `ㅋr지노`(ㅏ를 r로 바꿈), `ㅋㅏㅈ丨ㄴㅗ`(ㅣ를 한자 丨로 바꿈). JAMO는 확실하고, HOMOGLYPH도 q가 0.4를 넘는다고 본다.
- **추론으로 생긴 신호는 내지 않는다.** 예: display:none 안에서 기본 검정 글자의 대비를 계산한 결과는 신호가 아니다. 색 신호는 "글자색이나 투명도가 명시적으로 바뀐 경우"에만 인정한다. 계산된 color가 기본값과 다르거나, opacity·visibility가 기본값이 아니어야 한다.

### 4.3 부모에 숨김, 자식에 텍스트

```html
<div style="display:none"><a href="…">무료 슬롯 체험</a></div>
```

- 기본 location은 **텍스트를 가진 가장 안쪽 요소**(`a`)다. 근거는 모집요강 예시 4건이 모두 텍스트를 가진 말단 요소라는 점이다.
- **숨김 루트(div)가 광고 하나만 감싸고 있으면**(div의 텍스트 = a의 텍스트) 출제자가 div에 스타일을 걸었을 가능성이 반반이다. §0의 기준(p < 0.6)에 따라 **a와 div를 모두 출력한다.**
- 숨김 루트가 큰 컨테이너(메뉴 전체, 다른 정상 텍스트도 포함)면 텍스트 요소만 출력한다.
- 한 텍스트가 여러 인라인 자식으로 나뉘어 있으면(`<p>ㅋㅏ<b>ㅈㅣ</b>ㄴㅗ</p>`) 매칭 구간을 덮는 텍스트 노드들의 **최소 공통 조상**(p)을 location으로 쓴다.

## 5. HOMOGLYPH (닮은꼴 글자)

### 5.1 표준: UTS #39 skeleton

- 정의(UTS #39 v18.0 §4): `internalSkeleton(X)` = ① NFD ② Default_Ignorable_Code_Point 문자 제거 ③ 글자마다 confusables.txt의 prototype으로 치환 ④ 다시 NFD. `skeleton(X) = bidiSkeleton(LTR, X)`이고, `skeleton(X) = skeleton(Y)`이면 두 문자열은 혼동 가능하다. skeleton 문자열은 표시용이 아니고, 유니코드 버전이 바뀌면 다시 계산해야 하는 해시와 같은 중간 형태다. — [UTS #39 §4 Confusable Detection](https://www.unicode.org/reports/tr39/#Confusable_Detection)
- 데이터: [confusables.txt](https://www.unicode.org/Public/security/latest/confusables.txt) (2026-08-06판, 6,712개 항목), Default_Ignorable 목록은 [DerivedCoreProperties.txt](https://www.unicode.org/Public/UCD/latest/ucd/DerivedCoreProperties.txt)에 있다.
- 혼합 문자 체계 기준: UTS #39 §5.2의 "Highly Restrictive"는 **Latin + Han + Hangul(Kore)** 조합을 허용한다. 따라서 한글+영문+한자가 섞인 것 자체는 정상이다. 반면 라틴+키릴, 라틴+그리스 혼합은 Moderately Restrictive에서도 허용되지 않는다. — [UTS #39 §5.2](https://www.unicode.org/reports/tr39/#Restriction_Level_Detection)

### 5.2 ICU 없이 Python으로 구현 (직접 확인)

```python
import unicodedata as u
CONF = {chr(int(a,16)): ''.join(chr(int(x,16)) for x in b.split())
        for a,b,_ in (l.split('#')[0].split(';') for l in open('confusables.txt',encoding='utf-8-sig')
                      if l.strip() and not l.startswith('#'))}
IGN = {...}  # DerivedCoreProperties.txt의 Default_Ignorable_Code_Point 범위
def skeleton(s):
    s = u.normalize('NFD', s)
    s = ''.join(c for c in s if c not in IGN)
    s = ''.join(CONF.get(c, c) for c in s)
    return u.normalize('NFD', s)
```

- 외부 패키지가 필요 없다. 파일 2개(약 2MB)만 동봉하면 된다. 참고로 PyPI `confusable_homoglyphs`(3.3.1)는 `is_dangerous()`와 혼합 문자 판정을 제공하지만 skeleton 함수는 없다. — [confusable_homoglyphs API](https://confusable-homoglyphs.readthedocs.io/en/latest/apidocumentation.html)
- Python `unicodedata`의 유니코드 버전(로컬 3.14는 16.0)과 confusables 버전(18.0)이 다르지만, 정규화에 쓰는 부분은 영향이 거의 없다.

**직접 확인한 함정** (구현 시 반드시 반영)

| 입력 | skeleton 결과 | 의미 |
|---|---|---|
| `саsіnо`(키릴 혼합) | `casino` | 키릴 문자는 skeleton으로 풀린다 |
| `ｃａｓｉｎｏ` | `casino` | 전각 문자도 풀린다 |
| `mega-BET` vs `ｍｅｇａ－ＢＥＴ` | `rnega-BET` vs `rnegaーBET` | **다르다.** 전각 하이픈(U+FF0D)은 가나 장음 ー로 매핑된다. 그래서 **NFKC를 먼저 적용하고 skeleton을 적용**해야 한다 |
| `m` | `rn` | skeleton은 소문자화가 아니다. 키워드에도 똑같이 skeleton을 적용해서 비교한다 |
| `카지노` | `카ᄌ丨노` | 한글 음절이 NFD로 분해되고, ㅣ는 丨, ㅇ은 o로 바뀐다. **skeleton끼리만 비교**하고, 사용자에게 보여주는 정규화 문자열로는 쓰지 않는다 |
| `ㅋㅏㅈㅣㄴㅗ`, `카ㅈ丨노`, `카​지노` | 모두 `카ᄌ丨노` | 자모 분해, 한자 丨 치환, 제로폭 문자 삽입이 하나의 비교로 잡힌다 |
| `감` vs `ㄱㅏㅁ` | 둘 다 `가ᄆ` | confusables가 종성 ᆷ(U+11B7)을 초성 ᄆ(U+1106)으로 매핑하므로 받침 위치 차이가 사라진다 |
| U+200B, U+3164(한글 채움), U+115F, U+FFA0 | 제거됨 | 모두 Default_Ignorable이다 |

**confusables.txt에 들어 있는 한글 관련 항목** (직접 확인, 01·02 문서의 "한글-한자 대응이 없다"는 설명은 일부 틀렸다)
- 자모: 호환 자모(ㄱ U+3131), 반각 자모(ﾡ U+FFA1), 종성(ᆨ U+11A8)이 모두 초성 첫가끝 자모로 매핑된다. ㅇ→`o`, ㅣ→`丨`, ㅡ→`ー`(가나 장음), ㅐ→`ᅡ丨`, 겹자음·겹모음은 분해된다.
- 한자 → 한글: 丕→조, 卟→마, 今→ᄉーᄀ(슥), 合→ᄉーᄆ(슴), 丛→ᄉᄉー(쓰), 長→ᄐーᄂᄌ, 爿→누丨.
- 가나 → 한자: ロ·ﾛ→口, ト·ﾄ→卜, エ→工. **ㅁ↔口, ㅏ↔ト, ㄹ↔己 같은 한글↔가나·한자 대응은 없다.**

### 5.4 판정 알고리즘

```
homoglyph_tokens(raw):          # 토큰 = 공백으로 나뉜 문자열
  for tok in tokens(raw):
    A) NFKC(c) != c 이고 결과가 ASCII 영숫자인 글자(전각·수학·원문자·괄호문자)가 한 토큰에 2개 이상
       → 'compat-run'       예: ｍｅｇａＢＥＴ, 𝐁𝐄𝐓, ⓣⓞⓣⓞ
    B) 한 토큰에 라틴 + (키릴|그리스) 문자가 섞임, 또는 토큰 전체가 키릴·그리스인데 skeleton이 라틴 키워드와 같음
       → 'mixed-script'     예: саsіnо
    C) 한글 문맥에 한국어 닮은꼴 표의 글자가 있고, 되돌린 결과가 키워드 사전에 걸림
       → 'ko-lookalike'     예: 카지上, 亼포츠, ㅋr지노
    D) 라틴 단어 안의 숫자(leet)를 되돌리면(0→o, 1→i/l, 3→e, 4→a, 5→s, 7→t) 라틴 키워드에 걸림
       → 'leet'             예: t0t0, b3t, cas1no
HOMOGLYPH = (A|B|C|D 토큰이 1개 이상) AND ad_score(요소 전체) ≥ 기준
```

- A와 B는 키워드 일치를 요구하지 않는다. 모집요강 예시 `ｍｅｇａ－ＢＥＴ 첫충 30% 지급`에서 변형된 부분은 브랜드명이고, 광고 신호는 `첫충`, `30% 지급`이다. 그래서 **요소 단위 광고성**과 결합한다.
- C와 D는 흔한 글자를 쓰기 때문에 오탐 위험이 크다. 그래서 **키워드 일치를 반드시 요구한다.**

### 5.5 오탐 방지 (정상 문장)

직접 확인(규칙 A/B 프로토타입): `（주）`, `㈜`, `株式會社`, `국민(國民)`, `K-water`, `①②`, `Ⅱ`, `e-나라도움`은 신호가 없었다. `ＡＢＣ마트`, `ＬＧ전자`(전각 회사명), `10μg`(마이크로 기호)은 신호가 있었다. → 이 세 가지는 **광고성 점수에서 걸러지는 미끼**로 테스트 사이트에 넣는다.

| 정상 패턴 | 규칙 |
|---|---|
| 전각 괄호·문장부호(（ ）［ ］ ～ ％ ：) | 영숫자가 아니므로 A에서 세지 않는다 |
| 한자 병기 `국민(國民)`, 순한자 단어 | 한글 문맥이 아니므로 C에 해당하지 않는다. 한자 → 한글 대응은 키워드가 완성될 때만 인정한다 |
| 원숫자 목록 `①②③`, 원문자 `㉠㉡`, 로마 숫자 `Ⅰ Ⅱ` | 숫자·자음 하나만 있는 토큰은 A의 "영문자 2개 이상"에 걸리지 않는다. ㉠은 NFKC로 ᄀ이 되지만 모음이 없어서 JAMO 조합도 되지 않는다 |
| 단위 `μg`, `㎡`, `℃` | 숫자 뒤의 단위 기호는 예외로 둔다 |
| 전각 회사명, 오래된 HWP 변환 문서의 전각 영숫자 | 광고성 점수로 거른다 |

## 6. JAMO (자모 분해)

### 6.1 유니코드 범위와 조합 공식

| 블록 | 범위 | 비고 |
|---|---|---|
| 호환 자모 | U+3131–318E | 일반 키보드 입력. `ㅋㅏㅈㅣ` |
| 첫가끝(조합형) 자모 | U+1100–11FF, 확장 U+A960–A97F, U+D7B0–D7FF | 화면에는 **음절처럼 그려진다** |
| 반각 자모 | U+FFA0–FFDC | `ﾻￂﾸￜﾤￌ` |
| 원·괄호 자모 | U+3200–321E, U+3260–327E | NFKC로 자모가 된다 |

- 음절 공식: `S = 0xAC00 + (L×21 + V)×28 + T` (L 초성 19개, V 중성 21개, T 종성 28개, T=0은 받침 없음). — Unicode Standard §3.12 Conjoining Jamo Behavior ([Unicode 16.0 ch03](https://www.unicode.org/versions/Unicode16.0.0/core-spec/chapter-3/#G24646))
- **NFKC의 효과(직접 확인)**: 호환 자모와 반각 자모는 NFKC에서 첫가끝 초성·중성으로 바뀌고, 정규 합성으로 L+V가 음절이 된다. 그래서 `NFKC('ㅋㅏㅈㅣㄴㅗ') = '카지노'`, `NFKC('ﾻￂﾸￜﾤￌ') = '카지노'`, `NFKC('ㅂㅏㅋㅏㄹㅏ') = '바카라'`다. 하지만 받침 자리의 호환 자음도 **초성**으로 바뀌므로 `NFKC('ㄱㅏㅁ') = '가ᄆ'`(감이 아님)이 된다. 공백이 끼면 `ㅋ ㅏ ㅈ ㅣ`처럼 합성되지 않는다. → **자체 조합기가 필요하다.**
- 경고: 정규화를 먼저 해 버리면 JAMO 원문이 정상 텍스트처럼 보인다. **기법 분류는 항상 원문 글자로 한다.**

### 6.2 조합 알고리즘 (직접 확인)

```
compose(raw):
  atoms = [첫가끝·반각 → 호환 자모로 변환(NFKC 역표)]
  SEP = 공백 . , - _ · • * / | ~ ^ ✦★☆♡♥◆◇○● 와 제로폭 문자(U+200B–200F, 2060, FEFF), U+3164, U+115F, U+1160, U+FFA0, U+00AD
  i를 0부터 진행:
    초성 자음 C 다음(SEP 건너뜀)에 모음 V:
      V 다음이 모음 V2이고 (V,V2)가 겹모음(ㅗㅏ→ㅘ, ㅜㅣ→ㅟ, ㅡㅣ→ㅢ, ㅏㅣ→ㅐ, ㅓㅣ→ㅔ …)이면 합친다
      다음이 자음 T이고 그다음이 모음이 아니면 T를 받침으로 붙인다
        T 다음 자음 T2와 (T,T2)가 겹받침(ㄹㄱ→ㄺ …)이고 그다음이 모음이 아니면 겹받침
      음절 출력, 조합 수 +1
    그 밖의 글자는 그대로 출력
  return (문자열, 조합된 음절 수)
```

직접 확인 결과: `ㅋㅏㅈㅣㄴㅗ ㅂㅗㄴㅓㅅㅡ 코드 LUCKY7`→`카지노 보너스 코드 LUCKY7`(6음절), `ㅋ.ㅏ.ㅈ.ㅣ.ㄴ.ㅗ`→`카.지.노`, `ㅁㅓㄱㅌㅜㅣ`→`먹튀`, `ㅇㅏㄴㅈㅓㄴㄴㅗㄹㅇㅣㅌㅓ`→`안전놀이터`, `ㄷㅏㄹㄱㄱㅗㄱㅣ`→`닭고기`, 반각 `ﾻￂﾸￜﾤￌ`→`카지노`, 첫가끝 `카지노`(U+110F U+1161 …)→`카지노`, `ㅋ​ㅏㅈㅣㄴㅗ`→`카지노`. `ㅋㅋㅋ`, `ㅠㅠ`, `ㄱ. ㄴ. ㄷ.`, `ㅇㅋ`는 조합 수 0이었다.

- 매칭은 조합 결과에서 SEP를 지운 문자열로 한다(`카.지.노`→`카지노`).
- 원문 위치를 추적하려면 글자마다 (원문 인덱스 → 정규화 원자) 대응표를 유지한다. 그래야 매칭 구간의 원문 글자를 보고 기법을 분류할 수 있다(§6.4).

### 6.3 변형 대응

| 변형 | 처리 | 오탐 위험 |
|---|---|---|
| 호환·반각·첫가끝 자모 나열, 구분자·제로폭 문자 삽입 | 조합 후 정확 일치 | 낮음 |
| 가로 쪼개기(`ㅋr지노`, `스우ㅣㅊㅣ`) | 한국어 닮은꼴 표(r→ㅏ)를 적용한 뒤 조합 | 중간. 키워드 일치를 요구한다 |
| 받침 노이즈(`칧킪먻짞`) | 키워드와 후보를 **초성+중성 열**로 비교한다(종성 무시). 길이 3 이상 키워드만 대상으로 한다 | 높음(`통통`→토토). 다른 광고 신호가 함께 있을 때만 인정한다 |
| 오타·한 글자 변형 | 자모 단위 레벤슈타인 거리 ≤ 1(키워드 자모 수 ≥ 6일 때) | 중간 |
| 초성 약어(`ㅋㅈㄴ`, `ㅂㅋㄹ`, `ㅁㅌ`) | 키워드의 초성열 사전과 비교한다. **조합 음절이 0개라서 JAMO 기본 조건에 걸리지 않으므로**, 텔레그램 ID 같은 다른 광고 신호가 같은 요소에 있을 때만 JAMO로 낸다 | 높음(`ㅋㅋ`, `ㅌㅌ`, `ㄱㄱ`) |

- 자모 단위 편집거리를 쓰는 근거: 김수현 외, 「인터넷 채팅에서 편집거리 알고리즘을 이용한 비속어 탐지 방법」, 한국정보과학회 2018(01 문서 인용). DMoS(USENIX Security 2021)는 중국어 은어를 병음으로 바꾼 뒤 편집거리로 찾았다.
- KOTOX 규칙 분류(자음·모음 대치, 받침 변형, 연음, 기호 삽입, 띄어쓰기)를 **테스트 문자열 생성기**로 재사용할 수 있다(MIT). — [KOTOX augment_funtions/rule.py](https://github.com/leeyejin1231/KOTOX/blob/main/augment_funtions/rule.py)

### 6.4 판정 규칙

```
JAMO 판정:
  raw에 자모(호환·첫가끝·반각) 글자가 있고
  compose()로 조합된 음절이 2개 이상이며
  조합 결과(SEP 제거)가 광고 키워드에 걸리거나, 요소 전체의 ad_score가 기준 이상이고
  매칭 구간 또는 광고 문구 안에 자모 원문이 들어 있다
기법 분류 (매칭 구간의 원문 글자 기준):
  자모 글자 있음                              → JAMO
  NFKC/confusable/한국어 표로 바뀐 글자 있음   → HOMOGLYPH  (둘 다 있으면 2건)
  제로폭 문자·구분자만 있음                    → 4종 아님 (result_extra.json ETC "INVISIBLE_CHAR")
```

- 첫가끝 자모로만 쓰인 `카지노`는 화면에는 정상 음절로 보인다. 정의("음절을 자모 단위로 쪼개어 키워드 매칭을 우회")에 정확히 맞으므로 **JAMO**로 낸다.
- macOS에서 복사한 NFD 텍스트(파일명 등)는 정상인데도 첫가끝 자모로 들어온다. 이 경우는 광고성 점수와 §7.3의 부정 문맥으로 거른다.

### 6.5 정상 자모 오탐 방지

| 정상 패턴 | 왜 안 걸리나 |
|---|---|
| `ㅋㅋㅋ`, `ㅎㅎ`, `ㅠㅠ`, `ㅜㅜ`, `ㅇㅋ`, `ㄱㅅ` | 자음만 있거나 모음만 있어서 조합 음절이 0개다 |
| `ㄱ. ㄴ. ㄷ.`, `㉠ ㉡` 목록 번호 | 모음이 없다 |
| `ㅎㅏㅎㅏ` 같은 장난 표기 | 조합은 되지만 광고 키워드·광고성이 없다 |
| 한글 맞춤법 설명 글(`ㄱ+ㅏ=가`) | 광고성이 없다. 공공 사이트의 국어 교육 자료에 실제로 있다 |

## 7. 광고성 판정 (모든 기법의 공통 2단계)

### 7.1 키워드 사전 (출처 있는 것만 1군, 나머지는 2군)

| 분류 | 1군 (출처 확인) | 2군 (관행·추정, 테스트로 검증) |
|---|---|---|
| 도박 | 카지노, 보너스, 코드, 첫충, 지급, 먹튀검증, 안전놀이터, 슬롯, 체험, 바로가기, BET — 모집요강 13쪽 예시 / 첫충 200%, 친구 추천 시 지급, 공짜 충전, 무료 포인트 — [KB Think 2025-11-05](https://kbthink.com/savings/moneyclass/youth-gambling.html) / 꽁머니 지급 미끼 — 검색 결과 다수 | 토토, 바카라, 홀덤, 파워볼, 사다리, 매충, 롤링, 환전, 총판, 픽, 배팅/베팅, 스포츠중계, 놀이터, 메이저사이트 |
| 연락 수단 | 텔레그램 @ID — 모집요강 예시 `텔레그램 @promo_777`, 텔레그램 ID 100개 검색으로 go.kr 1,169건 — 매일경제 2025-11-16(01 문서) | 카톡, 오픈채팅, 라인, 위챗, 문의, 상담 |
| 마약 | 아이스, 시원한 술, 빙두(필로폰), 떨(대마), 캔디(엑스터시), 허브, 떨액상 — 문화일보 2021-06-09, 법률신문 보도(검색 결과) | 작대기, 던지기, 브액 |
| 불법 금융 | 통장 매매, 대포통장, 체크카드·OTP 매매, 작업대출("신용도와 관계없이 누구나 대출 가능"), 당일대출 승인, 급전대출, 휴대폰 소액결제·신용카드 현금화 — [찾기쉬운 생활법령 「불법금융광고」](https://www.easylaw.go.kr/CSP/CsmMain.laf?csmSeq=901) | 무직자 대출, 신불자, 개인돈, 유심 개통, 대포폰 |
| 성인 | (출처 미확보) | 출장안마, 조건만남, 오피, 성인, 19금, 야동, 비아그라·시알리스(불법 의약품) |

- 2군은 실제 공공 사이트 데이터로 검증하기 전까지 **단독으로는 광고 판정 근거로 쓰지 않는다.** 1군 키워드나 §7.2의 패턴과 함께 있을 때만 점수를 준다.
- 사전은 원형만 저장하고, 비교할 때 텍스트와 키워드 양쪽에 같은 정규화(`skeleton(NFKC(compose(x)))` 후 SEP 제거)를 적용한다.

### 7.2 패턴 (정규식은 정규화된 텍스트에 적용)

| 패턴 | 정규식 예 | 비고 |
|---|---|---|

| 텔레그램 링크 | `t\.me/[A-Za-z0-9_+]{3,}` | |

### 7.3 정상 공지와 구분 ("불법도박 예방" 미끼)

```
ad_score = Σ(1군 키워드 2점, 2군 1점, 패턴 3점) − 부정 문맥 점수
부정 문맥 (같은 요소 또는 제목·상위 블록): 예방, 근절, 단속, 신고, 처벌, 주의, 경고, 피해, 교육, 캠페인,
  유의, 금지, 차단, 상담센터, 1336(도박문제 상담전화), 경찰청, 금융감독원, 사행산업통합감독위원회, 보도자료
판정: ad_score ≥ 3 이고, 연락 수단·코드·퍼센트·도메인 패턴이 하나 이상 있으면 광고
```

- 숨김·변형 신호가 없는 정상 공지는 애초에 후보가 아니다(§1). 숨겨진 정상 공지(예: sr-only로 된 "불법도박 신고 안내")는 부정 문맥으로 거른다.
- 공지문에는 "행동 유도 + 연락처" 조합(가입, 코드, @ID, t.me)이 없다. 광고와 공지를 가르는 가장 강한 특징은 **연락 수단 패턴**이다. 그래서 1군 키워드만 있고 연락·코드·퍼센트 패턴이 없으면 광고로 보지 않는다. 단, 모집요강 예시 4 `무료 슬롯 체험 바로가기`처럼 패턴 없이 키워드와 행동 유도만 있는 경우가 있다. 그래서 "슬롯/카지노/바카라/토토 + 행동 유도어(바로가기, 가입, 체험, 지급)" 조합도 패턴과 같은 3점으로 친다.
- LLM 재판정(옵션): 점수가 경계(2~3점)인 후보만 `.env`에 키가 있을 때 판정을 요청한다(01 문서의 비용 원칙).

## 8. location 선택자 생성

### 8.1 모집요강 규칙 (11·12쪽)

1. 태그명과 클래스를 함께 쓰고, 상위 요소부터 ` > `(앞뒤 공백 1칸)로 연결한다. 예: `div.notice-board > span.visually-hidden`
2. 클래스가 없는 요소는 `tr:nth-of-type(7)`처럼 순서로 지정한다. 예시에는 `tr:nth-child(7)`도 쓰였다.
3. 속성값은 큰따옴표로 쓴다.
4. iframe 내부는 `iframe[src="절대URL"] >>> 선택자`로 쓰고, 중첩되면 `>>>`를 반복한다.
5. 작성 방식이 달라도 같은 요소를 정확히 가리키면 정답이다. 2곳 이상을 가리키면 오답이다.

### 8.2 생성 알고리즘

```
build_selector(E, doc):
  path = []
  for n in E, E.parent, ... (html 제외):
     seg = n.tagName.lower()
     cls = [c for c in n.classList if stable(c)]
     if cls: seg += '.' + '.'.join(css_escape(c) for c in best_subset(cls))
     else:   seg += f':nth-of-type({index_among_same_tag_siblings(n)})'
     path.insert(0, seg)
     sel = ' > '.join(path)
     if count(doc, sel) == 1 and doc.querySelector(sel) is E and static_ok(sel): break
  else: 마지막 수단으로 클래스가 있는 단계에도 :nth-of-type을 붙여서 고유하게 만든다
  return sel

stable(c): 해시·상태 클래스 제외
  - 해시: /^(css|sc|jsx|emotion|styled|svelte)-[\w-]{4,}$/, /^_[\w]{5,}$/, /[a-z]+_[a-zA-Z0-9]{5}$/(CSS Modules),
          자음 4개 이상 연속, 숫자와 문자가 3번 이상 번갈아 나옴 (finder의 wordLike와 같은 취지)
  - 상태: active, on, open, show, hover, focus, selected, current, is-*, has-*, ng-*, swiper-slide-*, slick-*, aos-*
  - 우리 도구가 추가한 하이라이트 클래스
best_subset(cls): 형제 중에서 이 요소만 갖는 클래스를 1개 고른다. 없으면 모든 안정 클래스를 쓴다
```

- 이 방식은 @medv/finder와 같은 구조다. 단계마다 후보(id, class, 속성, 태그, `:nth-of-type`, `:nth-child`)에 벌점을 주고, 벌점이 낮은 경로부터 `querySelectorAll` 결과가 정확히 1개인지 검사한 뒤, 중간 단계를 지워도 고유하면 지운다(optimize). 클래스 이름은 `wordLike`(3자 이상, 단어당 자음 4개 연속 금지)로 걸러서 해시 클래스를 뺀다. 다만 finder는 기본으로 **자손 결합자(공백)** 를 쓰고 id를 우선한다. 그래서 출력 형식을 우리 규칙(` > `, tag.class)으로 바꿔야 한다. — [antonmedv/finder finder.ts](https://github.com/antonmedv/finder/blob/master/finder.ts) (MIT)
- css-selector-generator(fczbkk)도 같은 "후보 조합 → 고유성 검사" 방식이다. 직접 구현해도 100줄 안팎이다.
- 탐색 중에 페이지가 바뀌지 않도록, 선택자는 **판정 직후 같은 문서 상태에서** 만들고 바로 검증한다.

### 8.3 정답 측 DOM과 어긋나는 위험 (직접 확인)

| 위험 | 확인 결과 | 대응 |
|---|---|---|
| 자동 삽입 `<tbody>` | 원본에 tbody가 없는 표에서 `div.board-list > table > tr`는 Chrome 0개, html.parser 2개, lxml 2개, html5lib 0개였다. `… > table > tbody > tr`는 그 반대였다 | 원본 HTML에 tbody가 없으면 그 구간을 **자손 결합자**로 쓴다. 예: `table.tbl tr:nth-of-type(2) > td.title > a`는 네 파서 모두에서 1개였다(브라우저 확인) |
| `:nth-child`와 `:nth-of-type` | `div.x`(p, span, p)에서 두 번째 p는 `p:nth-of-type(2)` = `p:nth-child(3)`이었다. `p:nth-child(2)`는 0개였다 | 모집요강 규칙대로 `:nth-of-type`을 쓴다 |
| JS가 형제를 끼워 넣음 | 렌더링 DOM과 원본 HTML의 순번이 다르다 | 클래스가 있는 조상에서 시작하는 짧은 경로를 쓴다. 순번 단계는 1개 이하로 줄인다 |
| 정답이 원본 HTML 기준인지 렌더링 DOM 기준인지 모름 | — | **이중 검증**: 렌더링 DOM에서 정확히 1개인지 보고, 그 요소가 원본 HTML에도 있으면(서버 렌더링) 원본 HTML(lxml + soupsieve)에서도 정확히 1개인지 본다. 둘 다 통과하는 선택자를 고른다 |

### 8.4 iframe

- 형식: `iframe[src="https://절대주소"] >>> div.wrap > span.hidden-link`. src는 **속성값을 절대 URL로 바꾼 값**으로 쓴다(모집요강 규칙). `frame.url`(리다이렉트된 뒤의 주소)이 아니라 **iframe 요소의 src 속성**을 `urljoin(문서 URL, src)`로 바꾼다.
- 같은 src를 가진 iframe이 2개 이상이면 앞에 고유한 조상 경로를 붙인다(`div.widget-b > iframe[src="…"] >>> …`).
- src가 없거나 `about:blank`이거나 srcdoc인 iframe은 규칙대로 쓸 수 없다. 이때는 `iframe:nth-of-type(n)` 경로로 쓰고, 이 항목은 정답과 맞지 않을 수 있다고 표시한다.
- **url 필드는 iframe을 품은 상위 페이지 URL이다**(모집요강 예시 f_004: url=`view?id=1180`, location=`iframe[src=".../widget/notice"] >>> …`). iframe src 페이지를 독립 페이지로 따로 보고하면 정답에 없는 항목이 될 가능성이 높다. 그래서 **iframe으로만 도달한 URL은 단독 보고하지 않는다.** 일반 링크로도 도달하는 경우는 테스트로 확인한다.
- 이스케이프: 속성값 안의 `"`와 `\`는 CSS 이스케이프(`\"`, `\\`)한다. JSON으로 저장하면 다시 `\"`가 된다(모집요강 13쪽 예시와 같다).

| 01 §3 JAMO | "연속된 자모를 음절로 다시 조합" | NFKC가 L+V는 합성하지만 받침을 초성으로 처리한다(`ㄱㅏㅁ`→`가ᄆ`). 자체 조합기가 필요하다. 또 정규화를 먼저 하면 JAMO 원문 정보가 사라지므로 기법 분류는 원문 글자로 한다 |
| 01 §3, 02 §2 | "checkVisibility()로 판정" | checkVisibility 기본값은 display:none과 content-visibility만 본다. 화면 밖 위치, 글자 크기, clip, 색, 가림은 보지 않는다. 요소 박스가 아니라 **텍스트 rect**를 봐야 text-indent를 잡는다 |
| 01 §3 TRANSPARENT | "WCAG 대비율로 1.1 이하 등" | 1.1이면 #eee(1.16)와 opacity 0.1(1.25)을 놓친다. **1.25를 권장**한다. 배경 이미지·그라데이션은 계산으로 판정할 수 없으므로 스크린샷 차분이 필요하다 |
| 02 §7 기법 경계 | 부모 숨김 + 자식 텍스트 → 자식 | 광고만 감싼 부모라면 부모와 자식 **둘 다 출력**하는 것이 기대 점수가 높다(§0, §4.3) |
| 02 §7 is_violation | 항상 true | 맞다. 추가로, **숨기지 않은 일반 광고**는 4종이 아니므로 result.json에 넣지 않는다는 규칙을 명시해야 한다 |
| 01 §4, 02 §7 location | finder 방식, querySelectorAll 1개 검증 | finder는 기본으로 자손 결합자와 id를 쓴다. 출력 형식을 바꿔야 한다. 또 **tbody 자동 삽입**(브라우저 vs 정적 파서) 때문에 원본 HTML 기준으로도 검증해야 한다 |
| 01 §4 iframe | page.frames로 접근 | location의 src는 `frame.url`이 아니라 **iframe 요소의 src 속성을 절대화한 값**이다. url 필드는 상위 페이지다. iframe으로만 도달한 URL은 단독 보고하지 않는다 |
| 02 §3 TRANSPARENT 변형 | visibility:hidden 포함 | 판단은 유지한다. 계열 기준으로 정하고 테스트로 고정한다(아래 판단 표) |

경계 사례에 대한 우리 판단 (평가 기준은 물어볼 수 없으므로 모집요강 문구·예시와 기대 점수로 정한다)

| 애매한 부분 | 판단 | 근거 |
|---|---|---|
| `visibility:hidden` | TRANSPARENT | 박스와 자리는 남고 그려지지만 않는다 (opacity:0과 같은 계열, §3) |
| `clip`, `text-indent`, 오버레이 가림 | OFFSCREEN | 배치·크기·렌더링 계열 속성 (§3) |
| 부모에 숨김, 자식에 텍스트 | 텍스트를 직접 가진 가장 안쪽 요소. 부모가 광고만 감싸고 있으면 부모와 자식 둘 다 출력 | 예시 정답이 모두 말단 요소, 기대 점수 계산(§0, §4.3) |
| location 기준이 원본 HTML인가 렌더링 DOM인가 | 렌더링 DOM으로 만들되, `tbody`처럼 자동 삽입되는 단계는 자손 결합자(공백)로 써서 **두 기준 모두에서 같은 요소 1개**를 가리키게 한다 | §5 tbody 실험 |
| iframe 문서 URL을 직접 방문해 찾은 항목 | 단독으로 출력하지 않는다 | 예시 정답의 url이 상위 페이지 |
