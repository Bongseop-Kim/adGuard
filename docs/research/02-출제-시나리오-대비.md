## 1. 숨기는 장소 (크롤링 커버리지)

| 장소 | 근거 | 대응 |
|---|---|---|
| 게시판 목록 제목 | 모집요강 예시 `tr:nth-child(7) > td.title > a` | 목록 페이지 자체도 분석 대상 |
| 게시글 본문 | 그누보드 스팸 사례: 정상 글처럼 보이게 쓰고 광고는 `sound_only`로 숨김 (gnustudy 2018) | 상세 페이지 전부 방문 |
| 댓글 | 모집요강 "댓글 영역" 명시 | 댓글 더보기, 댓글 페이지네이션 처리 |
| 목록 2쪽 이후 | 일반적인 게시판 구조 | 페이지 번호 링크 따라가기 (상한 있음) |
| 쿼리 값만 다른 상세 페이지 | 모집요강 `view?id=1024`, `view?id=1180` | 쿼리를 정렬해서 같은 페이지로 정규화, 값이 다르면 다른 페이지. `;jsessionid` 제거, 그누보드 `&page=N`처럼 내용이 같은 페이지는 1개만 분석 (03) |
| `onclick`·POST로만 열리는 글 | 전자정부 프레임워크 게시판은 `fn_egov_inqire_notice('130155', …)` 같은 JS로 상세를 연다 (행안부 누리집 확인) | 클릭을 가로채 요청(POST 본문 포함)을 큐에 넣는다. 이동은 `abort`한 뒤 다시 `goto`한다 (03 §3, 직접 확인). 전자정부 공통컴포넌트는 상세와 목록 2쪽 이후가 모두 POST다 |
| iframe 내부, 중첩 iframe, 다른 도메인 iframe | 모집요강 예시 `iframe[src=…] >>> …` | `page.frames` 전부 분석, 중첩은 `>>>` 반복. lazy iframe은 스크롤하고 프레임마다 타임아웃을 건다. src는 `frame.url`이 아니라 src 속성을 절대화한 값 (03) |
| 숨겨진 iframe (`width=0`, `display:none`) | 해킹으로 삽입된 숨김 링크 사례 (베트남 gov.vn 90개 사이트, 2023) | 숨김 iframe도 내부까지 분석 |
| JS가 나중에 넣는 요소 | 해킹 스크립트로 넣은 광고 (cside: 정부·대학 사이트 대상 ScriptAPI 공격) | `domcontentloaded` + DOM 변화가 멈출 때까지 대기(최대 3초) 후 분석. `networkidle`은 Playwright가 권장하지 않음 (03, 05) |
| 공통 영역 (푸터, 공지 위젯, 배너) | 해킹 삽입은 템플릿에 들어가서 모든 페이지에 나옴 | 페이지마다 1건씩 출력 (채점 단위가 url+location+technique) |
| 메뉴에 없는 옛 게시판 | 강원 청소년수련관 사례 (아시아투데이 2026) | `sitemap.xml`, `robots.txt`, 숨김 링크, 주석 속 URL까지 따라감 |
| `<title>`, `<meta>`, `alt`, `title` 속성 | DMoS(USENIX 2021): 검색 순위용으로 메타 태그에 넣음 | 속성 텍스트도 검사 (주요 4종에 해당하면 그 요소를 location으로) |
| CSS `::before`/`::after`의 `content` | CSS 표준상 가능 | 의사 요소의 content 문자열도 검사 |
| HTML 주석 | Talos: 주석을 이용한 salting | 추가 탐지(`result_extra.json`) 후보 |

## 2. OFFSCREEN 변형 목록

모집요강 기준: `font-size` 0~1px, `position:absolute; left:-9999px`, `display:none`

| 변형 | 근거 |
|---|---|
| `display:none` (자신 또는 조상), `hidden` 속성 | 모집요강, Talos |
| `font-size:0`, `font-size:1px`, `font-size:0.01em` | 모집요강, Talos ("1px + line-height") |
| `position:absolute/fixed` + `left/top:-9999px` | 모집요강 |
| `text-indent:-9999px` | 접근성 숨김 관행 |
| `transform: translate(-9999px)`, `scale(0)` | CSS 표준 |
| `margin-left:-9999px` | CSS 표준 |
| `width/height:0` 또는 `1px` + `overflow:hidden` | 접근성 `.blind` 관행, Talos (sizing) |
| `max-height:0`, `line-height:0` + `overflow:hidden` | Talos (preheader 사례) |
| `clip: rect(0 0 0 0)`, `clip-path: inset(100%)` | 접근성 `.sr-only` 관행, Talos (clipping) |
| `letter-spacing` 큰 음수 (글자가 한 점으로 겹침) | 그누보드 스팸 실사례 (gnustudy 2019) |
| 사이트 자체 숨김 클래스 재사용 (`sound_only`, `blind`, `visually-hidden`) | 그누보드 실사례, 모집요강 예시 `span.visually-hidden` |
| `overflow:hidden`인 조상 박스의 바깥에 위치 | CSS 표준 |
| 다른 요소에 가려짐 (`z-index`로 덮음) | CSS 표준 (판정 기준은 [§7](#7-필드-정확도-규칙)) |

판정 방법: 정적 스타일을 하나씩 대조하지 않는다. **텍스트 노드의 실제 글자 박스**(`getClientRects`)가 0 크기인지, 뷰포트·조상 클리핑 영역과 겹치지 않는지, 계산된 `font-size`가 1px 이하인지로 판단한다. 이렇게 하면 위 변형이 하나로 처리되고, 목록에 없는 새 변형도 잡힌다. `checkVisibility()` 기본값은 `display`와 `content-visibility`만 보므로 보조 수단으로만 쓴다. 요소 박스만 보면 `text-indent:-9999px`를 놓친다 (04, 직접 확인).

## 3. TRANSPARENT 변형 목록

모집요강 기준: 배경색과 같은 글자색, `opacity:0`, `color:transparent`

| 변형 | 근거 |
|---|---|
| `color` = 배경색 (흰 배경에 `#fff`, `#fefefe`처럼 거의 같은 색 포함) | 모집요강, Talos |
| 레거시 `<font color="#ffffff">` | 오래된 게시판 에디터의 HTML 허용 |
| 배경색이 조상에서 상속됨 (자신은 투명 배경) | CSS 표준. 조상을 거슬러 올라가 실제 배경 계산 |
| `color: transparent`, `rgba(…, 0)`, `hsla(…, 0)` | 모집요강 |
| `-webkit-text-fill-color: transparent` | CSS 표준 (color는 정상인데 글자는 안 보임) |
| `opacity:0` (자신 또는 조상, 누적 opacity ≈ 0) | 모집요강, Talos |
| `filter: opacity(0)` | CSS 표준 |
| `visibility:hidden` | Talos (visibility), 박스는 남고 보이지만 않음 |
| 배경 이미지·그라데이션 위의 같은 색 글자 | CSS 표준. 필요하면 해당 영역 스크린샷 픽셀로 판정 |

판정 방법: 글자색과 실제 배경색의 **WCAG 대비율이 1.25 미만**이면 판정한다. 1.1로 잡으면 `#eee`(1.16)와 opacity 0.1(1.25)을 놓친다. 누적 opacity는 조상을 곱해서 구한다. 배경이 이미지·그라데이션이면 글자를 투명하게 바꾼 스크린샷과 비교해서 차이가 없으면 판정한다 (04, 직접 확인).

## 4. HOMOGLYPH 변형 목록

모집요강 기준: 키릴·전각 문자, 숫자, 그 외 유사 문자를 섞어 사람 눈에는 같게 보이게 함. 예: `ｍｅｇａ－ＢＥＴ`

| 변형 | 예시 | 근거 |
|---|---|---|
| 전각 영문·숫자 | `ｂｅｔ`, `１２３` | 모집요강 예시, 스팸체 생성기 |
| 키릴·그리스 문자 | `саsіnо` (а, і, о가 키릴) | 모집요강, UTS #39 |
| 수학용 영숫자 | `𝐁𝐄𝐓`, `𝕓𝕖𝕥` | UTS #39 confusables |
| 원·괄호 문자 | `ⓣⓞⓣⓞ`, `❶❷`, `➀➁`, `㉠` | 스팸체 생성기 숫자표 |
| 한글 음절 → 비슷한 한자 | 스→亼, 고→卫, 소→仝, 수→㐃, 쓰→丛, 노→上, 조→丕, 쭈→卒, 곳→夬, 슥→今 | **스팸체 생성기 실제 변환표** |
| 숫자 → 한자·기호 | 1→丨, 2→己, 3→彐, 4→丩, 5→丂, 8→日 | 스팸체 생성기 |
| 한글 자모 → 가나·한자 | ㅁ→ロ/□, ㅈ→ヌ, ㄹ→己, ㅏ→ト, ㅍ→工 | 스팸체 생성기, 시각적 유사성 |
| 한글 자모 → 라틴·숫자 | ㄱ→7, ㅏ→r, ㅇ→o/0, ㅣ→l/1, ㅂ→ㅂ(H) | 스팸체 생성기 `7r ㄴr` |
| 라틴 → 숫자 (leet) | `b3t`, `s1ot` | Bad Characters, KOTOX(시각 변형) |

판정 방법:
1. NFKC 정규화로 전각, 원문자, 수학 문자를 처리한다.
2. UTS #39 `confusables.txt`로 키릴, 그리스 문자를 처리한다.
3. **한국어 전용 닮은꼴 표**로 한자, 가나, 기호를 한글로 되돌린다. confusables에도 일부(丕→조, 今→슥, 丛→쓰, 丨→ㅣ)는 있다. 하지만 亼, 卫, 仝, 上, 己, ロ, r 등은 없다. 그래서 confusables, 스팸체 생성기, KOTOX 사전(MIT)을 합쳐서 만든다 (04).
4. 비교는 `skeleton(NFKC(x))`끼리 한다. 기법 코드는 정규화 전 원문에서 실제 치환된 글자를 보고 정한다 (04).
5. 판정 조건:
   - 전각·키릴·수학 문자처럼 **문자 체계 자체가 섞인 경우**: 같은 요소에 광고성 내용이 있으면 판정한다. 모집요강 예시 `ｍｅｇａ－ＢＥＴ`는 키워드 사전에 없는 브랜드명이기 때문이다.
   - 한국어 닮은꼴 표나 leet처럼 **흔한 글자로 만든 닮은꼴**: 정상 문장에서도 자주 나오므로 키워드 매칭까지 요구한다.

## 5. JAMO 변형 목록

모집요강 기준: 음절을 자모 단위로 쪼개 키워드 매칭을 우회. 예: `ㅋㅏㅈㅣㄴㅗ`

| 변형 | 예시 | 근거 |
|---|---|---|
| 호환 자모 나열 | `ㅋㅏㅈㅣㄴㅗ` | 모집요강 예시 |
| 사이에 공백·특수문자 | `ㅋ ㅏ ㅈ ㅣ`, `ㅋ.ㅏ.ㅈ.ㅣ`, `ㅋ✦ㅏ` | 스팸체 생성기 "특문 삽입" |
| 가로 쪼개기 (음절 일부만 분리) | `스위치` → `스우ㅣㅊㅣ`, `카지노` → `ㅋr지노` | 스팸체 생성기 |
| 초성만 | `ㅋㅈㄴ`, `ㅌㅌ`, `ㅂㅋㄹ` | 한국어 은어 관행 |
| 첫가끝 자모 (U+1100~) | 화면에는 정상 음절처럼 보이지만 코드값은 자모 | 유니코드 표준. NFC 정규화로 복원 가능 |
| 반각 자모 (U+FFA0~) | `ﾡﾷ` | 유니코드 표준 |
| 받침 노이즈 | `칧킪먻짞` (치킨먹자) | 스팸체 생성기 "초성·종성 복잡하게" (KOTOX 음운 변형) |
| 자모 사이 보이지 않는 문자 | `ㅋ​ㅏ` (U+200B), 한글 채움 문자 U+3164 | Talos (ZWSP/ZWNJ 삽입), Bad Characters |

판정 방법: 보이지 않는 문자와 구분자를 지운다 → NFC → 연속된 자모를 음절로 조합한다 → 키워드와 비교한다(자모 단위 편집 거리로 받침 노이즈까지 허용). `ㅋㅋㅋ`, `ㅠㅠ` 같은 정상 표현은 조합 결과가 키워드에 걸릴 때만 잡는다.

## 6. 미끼 (정확도 35점을 지키는 목록)

| 미끼 | 실제 근거 | 왜 잡으면 안 되나 |
|---|---|---|
| 접근성 숨김 텍스트 ("본문 바로가기", "새창으로 열기") | 행안부 누리집 한 페이지에 716건 (직접 측정) | 공공 사이트는 웹 접근성 인증이 의무라 모든 페이지에 있다 |
| 접힌 메뉴, 닫힌 탭·모달·드롭다운 (`display:none`) | 같은 측정에서 메뉴 전체가 숨김 | 정상 UI |
| 정상 전각 문자, 한자 (`（주）`, `株式會社`, `①②`) | 공문서 관행 | 광고 키워드가 아님 |
| 정상 자모 (`ㅋㅋ`, `ㅠㅠ`, `ㄱ. ㄴ. ㄷ.` 목록 번호) | 공문서 목록 기호 | 광고 키워드가 아님 |
| "불법도박 예방 교육 안내" 같은 정상 공지 | 공공기관 업무 특성 | 키워드는 있지만 숨김·변형이 없음 |
| 흐린 회색 안내문 (대비가 낮지만 읽힘) | 디자인 관행 | 대비율 임계값을 엄격하게 둠 |

규칙: **숨김·변형 신호와 광고성 내용이 둘 다 있을 때만** 출력한다.

## 7. 필드 정확도 규칙

| 필드 | 규칙 | 근거 |
|---|---|---|
| `url` | 페이지는 리다이렉트된 뒤의 최종 URL, `#` 이하는 제거. iframe 안의 항목은 **상위 페이지 URL**. POST로만 열리는 글은 GET으로 같은 글이 열리면 GET URL(파라미터 포함) | 채점이 `#`, 끝 `/`, http/https 차이를 무시함. 예시 정답의 url이 상위 페이지 (03 §8) |
| `location` | 근거 텍스트를 직접 가진 가장 안쪽 요소. 출력하기 전에 **렌더링 DOM과 원본 HTML 양쪽에서** 결과가 정확히 1개인지 검증. `tbody`처럼 자동 삽입되는 단계는 자손 결합자(공백)로 쓴다 | 모집요강 예시가 모두 말단 요소, 2곳 이상을 가리키면 오답. 브라우저는 `tbody`를 넣고 정적 파서는 넣지 않음 (04, 직접 확인) |
| `location` (iframe) | `iframe[src="절대URL"] >>> 선택자`, 중첩되면 반복 | 모집요강 |
| `technique` | 1건에 코드 1개. 기법이 겹치면 기법마다 따로 1건 | 모집요강 |
| 같은 요소, 같은 기법 문자열 여러 개 | 1건으로 묶음 | 모집요강 |
| `evidence_text` | 정규화 전 원문 그대로 | 모집요강 |
| `is_violation` | 항상 `true` (위반만 출력) | 정상 요소를 넣으면 정확도만 떨어짐 |
| 숨기지 않은 일반 광고 | `result.json`에 넣지 않고 `result_extra.json`에 ETC로 넣음 | 4종이 아님. 모집요강의 "게시되거나 숨겨진"에는 extra로 대응 |
| 파일 저장 | UTF-8(BOM 없음)을 명시하고, 임시 파일에 쓴 뒤 이름을 바꿔 원자적으로 저장 | Windows 기본 인코딩이 cp949 (04, 05) |
| `id` | `f_001`부터 순서대로, 중복 없이 | 스키마 |

### 기법 경계에서의 판단

| 경우 | 판단 |
|---|---|
| `visibility:hidden` | TRANSPARENT (박스는 남고 보이지만 않음) |
| `clip`, `text-indent`, `letter-spacing` 음수, 크기 0 | OFFSCREEN (박스가 사라지거나 밀려나거나 줄어듦) |
| `ㅋr지노`처럼 자모 쪼개기와 닮은꼴 치환이 한 문자열에 있음 | JAMO와 HOMOGLYPH 둘 다 출력 ("중첩 적용 시 기법별 별도 객체" 규칙) |
| 숨김 요소 안의 텍스트가 HOMOGLYPH이기도 함 | 숨김 기법 1건 + HOMOGLYPH 1건 |
| 부모에 숨김 스타일, 자식에 텍스트 | 텍스트를 가진 자식 요소를 location으로. 부모가 광고만 감싸고 있으면 부모와 자식 둘 다 출력 (기대 점수 계산, 04 §0) |
| 기법 코드 일반 규칙 | 색·투명 계열 속성이면 TRANSPARENT, 배치·크기·렌더링 계열이면 OFFSCREEN. 두 계열이 다 걸리면 2건 (04) |
| 같은 도메인 iframe의 src 페이지 | 단독으로 출력하지 않음. 상위 페이지 + `iframe[src] >>>`로 1번만 (03 §8) |

## 8. 시간 (20점)

- **분석할 페이지는 모두 렌더링한다.** 숨김 판정에는 계산된 스타일이 필요하고, JS로 넣는 광고도 있다. 정적 요청(`context.request`)은 `robots.txt`, `sitemap.xml`, JS 파일 속 링크 수집에만 쓴다 (03, 05).
- 이미지, 폰트, 미디어만 차단한다. **CSS와 JS는 막지 않는다.** 분석 스크립트는 알려진 외부 분석 도메인만 막는다.
- 브라우저 1개 + 컨텍스트 4~6개(RAM에 따라 자동 조정). 8GB PC에서 8개는 위험하다.
- 브라우저는 앱을 켤 때 미리 띄워 둔다. 측정은 "탐지 시작" 클릭부터다.
- "탐지 완료"는 `result.json`을 다 쓴 다음 표시한다.
- 내부 데드라인: 소프트 20분(새 페이지 방문 중단), 하드 25분(즉시 저장).
- 전체 상한은 20분이다. 넘으면 그때까지의 결과로 `result.json`을 저장한다.
- 목표는 5분 이내다.
