# 검출 시간·실행 환경·도입 가능성 조사

- 작성: 2026-10-14
- 담당 평가 항목: 적격평가 **검출 시간 20점**, 본심사 **도입 가능성 10점**, 그리고 실행 실패로 인한 **전 항목 0점 방지**
- 근거: 모집요강 2·6~9쪽(제출물, 검출 시간, 평가 PC, AI API 규칙) + 아래 출처

## 핵심 결론

1. **실행이 안 되면 100점이 다 날아간다. 속도보다 "깨끗한 Windows 11에서 무조건 뜨는 것"이 먼저다.** PyInstaller는 **onedir**로 만들고(onefile 금지), UPX는 끄고, 브라우저는 **exe 옆 폴더에 Chromium headless shell을 넣어 `executable_path`로 직접 지정**한다. Edge(`msedge`)는 1순위가 아니라 **폴백**이다.
2. **시간은 "탐지 시작" 클릭부터 잰다.** 브라우저 기동·워밍업은 앱을 켤 때 미리 끝내 둔다. 렌더링은 1개 브라우저 + 컨텍스트 4~6개 병렬, 이미지·폰트·미디어만 차단(**CSS·JS는 차단 금지**, 숨김 판정에 필요), `networkidle` 대신 `domcontentloaded` + 짧은 안정화 대기. 목표는 **테스트 사이트 전체 5분 이내**, 내부 하드 상한 20분.
3. **제출 파일이 200MB 안팎이 된다. 이메일 첨부로는 못 보낸다**(Gmail 등은 zip 안의 exe도 차단). 대용량 링크로 내고, 접수 방법(용량·링크 제출 가능 여부)만 주최 측(1555-6365)에 확인한다. 평가 내용이 아니라 접수 절차 확인이다. 미서명 exe라 SmartScreen 경고가 뜨므로 사용설명서 첫 장에 "추가 정보 → 실행" 안내를 넣는다.
4. **AI는 기본 꺼짐 + 후보만 묶어서 호출 + 캐시 + 타임아웃 시 규칙 폴백.** `.env`는 `exe 옆 경로`를 명시해서 읽는다(`override=True`). 키가 없거나 네트워크가 막혀도 결과는 그대로 나와야 한다. 토큰 사용량을 화면과 로그에 보여 주면 도입 가능성(비용) 설명이 쉬워진다.
5. **UI는 로컬 웹 UI(127.0.0.1 바인딩, 표준 라이브러리 서버) + Edge `--app` 창**이 패키징·안정성 모두 가장 낫다. 데스크톱 GUI 프레임워크는 쓰지 않는다. `result.json`을 다 쓴 다음에 "탐지 완료"를 표시한다.

**추천 스택 한 줄:** Python 3.12 + Playwright(버전 고정) + 번들 Chromium headless shell(Edge 폴백) + PyInstaller 6 onedir(UPX 끔) + 표준 라이브러리 HTTP 서버 로컬 웹 UI + 선택적 OpenAI 호출(.env).

## 2. 속도: Playwright로 많은 페이지를 빨리 분석하기

### 2.1 설정별 권장값

| 항목 | 권장 | 근거 |
|---|---|---|
| 브라우저 수 | **브라우저 1개**, 그 안에 `new_context()` 여러 개 | Playwright는 브라우저 기동이 무겁고 컨텍스트는 가볍다. 컨텍스트별로 쿠키·스토리지가 분리된다 ([browserstack](https://www.browserstack.com/guide/playwright-browser-context), [dev.to](https://dev.to/deepak_mishra_35863517037/scaling-headless-browsers-managing-contexts-vs-instances-1d73)) |
| 병렬 수 | **4~6 (기본 4)**, 가용 RAM으로 자동 조정: `min(6, (가용RAM_GB-1.5)/0.4, CPU코어)` | 헤드리스 세션당 대략 300~500MB 가정 ([Railway browserless 템플릿](https://railway.com/deploy/browserless-headless-chrome)), 탭당 150~300MB라는 자료도 있다 ([webscraping.ai](https://webscraping.ai/faq/headless-chromium/what-are-the-resource-requirements-for-running-headless-chromium-at-scale)). 공식 수치는 없으므로 실측으로 정한다 |
| 대기 전략 | `goto(wait_until="domcontentloaded")` → `load`를 최대 3~5초 기다림 → DOM 변화가 300~500ms 없을 때까지(최대 1.5초) 대기 | Playwright 공식 문서가 `networkidle`을 **DISCOURAGED**로 표시 ([page.goto](https://playwright.dev/python/docs/api/class-page#page-goto)). 분석 스크립트·폴링이 있으면 500ms 유휴가 끝나지 않는다 |
| 리소스 차단 | `resource_type in {"image","media","font"}`만 `abort`. 알려진 외부 분석 도메인(google-analytics 등)만 추가 차단 | 공식 예시가 `resource_type`으로 차단 ([network](https://playwright.dev/python/docs/network)). **stylesheet·script는 막으면 안 된다**: 투명·화면 밖 판정은 계산된 스타일이 필요하고, JS가 나중에 넣는 광고도 있다(02 §1) |
| 서비스 워커 | `new_context(service_workers="block")` | 서비스 워커가 요청을 가로채면 `route`가 못 본다 ([network](https://playwright.dev/python/docs/network)) |
| 타임아웃 | 페이지당 이동 15초, 분석 10초. 실패 페이지는 1회 재시도 후 건너뜀 | 기본 타임아웃 30초를 그대로 두면 죽은 링크 몇 개가 시간을 다 먹는다 ([class-page](https://playwright.dev/python/docs/api/class-page)) |
| HTTPS | `new_context(ignore_https_errors=True)` | 기본값 `false` ([new_context](https://playwright.dev/python/docs/api/class-browser#browser-new-context)). 테스트 사이트가 자체 서명 인증서일 수 있다 |
| 화면 크기 | `viewport` 1280×720, `device_scale_factor=1` 고정 | 기본값이 1280×720·dpr 1이다 ([new_context](https://playwright.dev/python/docs/api/class-browser#browser-new-context)). 평가 PC의 해상도·배율과 무관하게 화면 밖 판정이 같아진다 |
| 분석 방식 | 페이지마다 `evaluate()` 1회로 모든 텍스트 노드의 계산된 스타일·좌표·선택자를 한 번에 뽑아 온다 | 요소마다 Python↔브라우저 왕복을 하면 수천 번 IPC가 생긴다(Playwright Python은 Node 드라이버를 거친다) |
| iframe | `page.frames` 각각에서 같은 `evaluate()` 실행 | 01 §4와 같음 |

### 2.2 "정적 HTML 선수집 후 선택적 렌더링"에 대한 정정

- **링크 수집에는 유효, 분석 생략에는 무효.** 투명·화면 밖 판정은 외부 CSS까지 적용된 계산 스타일이 있어야 하므로, **분석할 페이지는 전부 렌더링해야 한다.** 정적 HTML만으로는 `class="hide"`가 실제로 숨기는지 알 수 없다.
- 쓸 곳: (1) `sitemap.xml`·`robots.txt`·목록 페이지의 링크를 빨리 모아 렌더링 대기열을 미리 채운다. (2) 같은 템플릿의 정적 HTML 해시가 같으면 중복 URL을 빨리 거른다(단, 쿼리 값이 다르면 다른 페이지라는 채점 규칙 때문에 **해시가 같아도 각 URL을 결과에 내야 하는지**는 별도 규칙으로 판단).
- 정적 요청은 Python `httpx/requests`가 아니라 **`context.request`(Playwright APIRequestContext)**로 보낸다. 브라우저 컨텍스트와 쿠키를 공유하고 `ignore_https_errors`를 지원하므로 인증서·쿠키 문제를 따로 처리할 필요가 없다 ([APIRequestContext](https://playwright.dev/python/docs/api/class-apirequestcontext)).

### 2.3 처리량 목표치와 근거

공개된 "CPU 전용 PC에서 Playwright 페이지/분" 벤치마크는 찾지 못했다. Crawlee 공식 문서도 고정 수치 없이 CPU·메모리 여유에 따라 자동 조절한다고만 한다 ([Crawlee PlaywrightCrawler](https://crawlee.dev/api/playwright-crawler)). 그래서 아래는 **가정 기반 추정**이고, `todo` 단계에서 실측으로 갱신해야 한다.

| 가정 | 값 |
|---|---|
| 평가 PC | 4코어/8스레드, RAM 8~16GB (일반 사무용) |
| 테스트 사이트 | 주최 측이 만든 가벼운 사이트(게시판·댓글·iframe), 페이지당 HTML+CSS+JS 수백 KB, LAN 또는 빠른 회선 |
| 페이지 1개 처리 시간(탭 1개) | 이동+안정화 0.7~2초 + 분석 `evaluate` 0.1~0.5초 |

| 지표 | 목표 | 계산 |
|---|---|---|
| 처리량 | **분당 120페이지 이상**(병렬 4) | 탭 1개 분당 30~60페이지 × 4 |
| 테스트 사이트 규모별 완료 시간 | 100페이지 1분 이내, 300페이지 3분 이내, 1,000페이지 10분 이내 | 위 처리량 기준 |
| 브라우저 기동 | 측정 구간 밖에서 미리 수행 | 앱 시작 시 `launch()` + 빈 페이지 1회 로드로 워밍업 |
| 내부 상한 | 20분에 탐색 중단 → 그때까지 결과로 `result.json` 작성 | 30분 초과 시 0점(6쪽). 쓰기·정리 시간 여유 |

- 시간 점수가 상대평가(순위)인지 절대평가(구간)인지 모집요강에 없다. **정답 검출 45점이 시간 20점보다 크므로** 상한 안에서는 커버리지를 우선한다. 단, 같은 템플릿 반복 페이지(정렬·페이지 번호만 다른 URL)는 상한(예: 게시판당 목록 10쪽)을 둔다.

## 3. Windows 배포 (PyInstaller + Playwright + Chromium)

### 3.1 무엇이 실패하나 → 근거 → 대응

| 실패 | 근거 | 대응 |
|---|---|---|
| 실행 시 "Executable doesn't exist" (브라우저를 못 찾음) | 설치 때와 실행 때 브라우저 경로가 다르면 발생 ([Apify 포럼](https://discord.apify.com/m/1407791935267278878), [HF 포럼](https://discuss.huggingface.co/t/executable-doesnt-exist-at-root-cache-ms-playwright-chromium-1200-chrome-linux64-chrome/171806)). 실행 중에 환경변수를 바꾸면 이미 늦을 수 있음 ([playwright#4808](https://github.com/microsoft/playwright/issues/4808)) | 공식 방법은 `PLAYWRIGHT_BROWSERS_PATH=0`으로 설치 후 `pyinstaller -F` ([Playwright 공식](https://playwright.dev/python/docs/library)). 우리는 **더 명시적으로**: `browsers/chrome-headless-shell-win64/`를 exe 옆에 두고 `chromium.launch(executable_path=<exe폴더>/browsers/.../chrome-headless-shell.exe)`로 지정. 실패 시 `channel="msedge"`로 재시도 |
| onefile이 느리고 찌꺼기를 남김 | onefile은 매 실행마다 `_MEIxxxx` 임시 폴더에 풀고, 강제 종료 시 이 폴더가 남는다. 공식 문서가 onedir로 먼저 동작 확인하라고 권함 ([PyInstaller 동작 모드](https://pyinstaller.org/en/stable/operating-mode.html)) | **onedir 사용**. Chromium 수백 MB를 매번 임시 폴더에 푸는 것은 기동 지연 + 백신 재검사 대상 |
| `result.json`이 임시 폴더에 생김 | onefile에서 `sys._MEIPASS`·`__file__`은 임시 폴더, `sys.executable`은 실제 exe ([PyInstaller 런타임 정보](https://pyinstaller.org/en/stable/runtime-information.html)) | `BASE = Path(sys.executable).parent if getattr(sys,"frozen",False) else Path(__file__).parent`. 결과·`.env`·로그 모두 `BASE` 기준 |
| exe 폴더가 쓰기 불가(예: `Program Files`, 읽기 전용 USB) | 관리자 권한 없는 사용자 | 쓰기 테스트 실패 시 `%LOCALAPPDATA%\adGuard\`에 쓰고 **화면과 로그에 실제 경로 표시**. 사용설명서 첫 장에 대체 경로 명시(9쪽 요구) |
| Windows에서 asyncio `NotImplementedError` | Windows는 Proactor 루프만 서브프로세스 지원. 다른 라이브러리가 Selector 정책을 강제하면 Playwright가 브라우저를 못 띄움 ([scrapy-playwright#7](https://github.com/scrapy-plugins/scrapy-playwright/issues/7), [CPython 문서](https://git.joshthomas.dev/mirrors/cpython/src/branch/3.11/Doc/library/asyncio-platforms.rst)) | 이벤트 루프 정책을 건드리지 않는다. 웹 UI 서버는 표준 라이브러리 스레드 서버로 분리해서 Playwright 루프와 충돌하지 않게 한다 |
| 버전 업으로 동작 변화 | Playwright 1.64.0이 2026-10-13에 나왔다(PyPI). 1.63.0은 2026-09-15 | 지금 쓰는 버전을 `requirements.txt`에 `==`로 고정하고 제출 전까지 올리지 않는다 |

### 3.2 크기 (실측 근거)

| 구성 | 크기 | 출처 |
|---|---|---|
| Playwright 1.64.0 win_amd64 wheel (Node 드라이버 포함) | 38.7MB (압축) | [PyPI JSON](https://pypi.org/pypi/playwright/json) |
| Chrome for Testing 156 `chrome-win64.zip` (풀 Chromium) | 207MB (압축) | `storage.googleapis.com/chrome-for-testing-public/156.0.8078.4/win64/` HEAD 요청 (Playwright 1.64 `browsers.json`의 chromium 1248 = 156.0.8078.4) |
| `chrome-headless-shell-win64.zip` | **124MB** (압축) | 같은 경로 HEAD 요청 |
| 참고: macOS 압축 해제 크기 | chromium 366MB, headless shell 203MB | 로컬 `~/Library/Caches/ms-playwright` |

- **headless shell만 넣는다**(`playwright install chromium --only-shell`). 헤드리스 기본 실행은 원래 headless shell을 쓴다 ([Playwright 브라우저 문서](https://playwright.dev/python/docs/browsers)). 풀 Chromium보다 80MB 이상 작다.
- 예상 배포본: Python 런타임+의존성 30~50MB + 드라이버 ~40MB + headless shell 124MB → **zip 약 200MB, 압축 해제 약 400MB**. 이메일 첨부 한도를 넘는다(§4 참고).

### 3.3 Edge(`channel="msedge"`)를 1순위로 쓰지 않는 이유

| 장점 | 단점 |
|---|---|
| Windows 11 기본 탑재, 배포 크기 0 | 기업 정책 `RemoteDebuggingAllowed`를 끄면 `--remote-debugging-pipe`도 막힌다고 MS 공식 문서가 명시 ([MS Learn](https://learn.microsoft.com/en-us/deployedge/microsoft-edge-browser-policies/remotedebuggingallowed)). Playwright는 파이프로 브라우저를 제어하므로 실행 자체가 실패할 수 있음 |

### 6.3 `.env` 로딩

```python
from pathlib import Path
import sys, os
from dotenv import load_dotenv

BASE = Path(sys.executable).parent if getattr(sys, "frozen", False) else Path(__file__).resolve().parent
for name in (".env", ".env.txt"):
    p = BASE / name
    if p.is_file():
        load_dotenv(p, override=True, encoding="utf-8-sig")  # BOM 있어도 읽힘
        break
```

- `load_dotenv()`는 기본적으로 **호출한 스크립트 위치부터** 찾는다 ([python-dotenv](https://github.com/theskumar/python-dotenv)). frozen 앱에서는 그 위치가 `_internal`/임시 폴더이므로 **경로를 명시**해야 한다.
- 기본 `override=False`라 PC에 같은 이름 환경변수가 있으면 `.env`가 무시된다 ([python-dotenv](https://github.com/theskumar/python-dotenv)). 주최 측 키가 확실히 쓰이도록 `override=True`.
- 환경변수 이름(예): `OPENAI_API_KEY`, `ADGUARD_AI_MODEL`(기본 `gpt-5-mini`), `ADGUARD_AI_ENABLED`(기본 auto), `ADGUARD_PROXY`(선택). 사용설명서에 표로 명시.
- 키 값은 로그·화면·`result.json`에 절대 출력하지 않는다(앞 4자리만 마스킹 표시).

시간 측정 규칙:

1. 앱 실행 → 브라우저 기동·워밍업 → 화면에 "준비 완료" 표시 (여기까지는 측정 구간 밖).
2. URL 입력 → **"탐지 시작"** 클릭 시각을 `meta.started_at`으로 기록.
3. 진행 화면: 방문 페이지 수/대기열, 검출 수, 경과 시간, 현재 URL, AI 상태.

5. `elapsed_sec` = finished − started. 화면 표시 값과 파일 값이 같아야 한다.
6. 보조로 CLI 모드 `adGuard.exe --url <URL> --no-ui` 제공(심사자가 자동화할 때 대비, 사용설명서에 명시).

| Node.js SEA 단일 exe | SEA는 "Active development(1.1)", VFS는 "Early development(1.0)", 네이티브 애드온·외부 파일 제약 ([Node.js SEA](https://nodejs.org/api/single-executable-applications.html)) | 브라우저는 결국 별도 폴더 | 비슷 | 서명 제거 후 주입 → 미서명 | 9일 남은 상황에서 위험 |
| Go + chromedp | 단일 바이너리, 의존성 없음 ([chromedp](https://github.com/chromedp/chromedp)). 브라우저는 별도(Edge 지정 가능) | 10~20MB + 브라우저 | 빠름 | Go 바이너리도 오탐 잦음(Go FAQ 인정) ([golangbridge](https://forum.golangbridge.org/t/my-compiled-exe-file-is-declared-as-a-virus/34038)). `--remote-debugging-port` 사용 → Edge 정책에 막힐 수 있음 | 재작성 비용 대비 이득 작음 |
| Rust (chromiumoxide 등) | 단일 바이너리 | 작음 | 빠름 | 낮음~중간 | 개발 기간 부족 |

결론: 병목은 언어가 아니라 **Chromium 렌더링**이다. Python을 유지하고 패키징 위험을 §3·§9로 줄인다.

## 9. 제출 전 검증 체크리스트 (깨끗한 Windows 11에서)

**환경 준비**
- [ ] Python·Node·Chrome이 **설치되지 않은** Windows 11 VM(또는 새 PC), 일반 사용자 계정(관리자 아님), Defender 실시간 보호·SmartScreen 켬
- [ ] 한글 사용자 계정(예: `홍길동`)으로 한 번 더
- [ ] 화면 배율 100%와 150% 각각

**배포본**
- [ ] 제출과 **같은 zip**을 실제 제출 경로(대용량 링크)로 내려받아 테스트(MotW가 붙은 상태)
- [ ] 탐색기 기본 압축 풀기로 해제, 경로 `C:\Users\홍길동\바탕 화면\공모 제출 테스트\adGuard\`(한글+공백)
- [ ] SmartScreen 경고 → "추가 정보 → 실행"으로 실행되는지, 설명서 스크린샷과 일치하는지
- [ ] Defender 전체 검사·VirusTotal에서 exe와 폴더 전체 탐지 0건(결과 캡처 보관), SHA-256 기록
- [ ] 압축 해제 크기·zip 크기 기록, 링크 만료일이 11.4 이후

**실행**
- [ ] 더블클릭 → 30초 안에 UI 표시, "준비 완료" 상태
- [ ] 번들 브라우저로 실행되는지 로그 확인 / 번들 폴더 이름을 바꿔서 Edge 폴백 동작 확인 / 둘 다 없을 때 오류 안내 확인
- [ ] 인터넷 끊고 로컬 테스트 사이트만 접근 가능한 상태에서 정상 완료
- [ ] 자체 서명 HTTPS 테스트 사이트에서 정상 완료
- [ ] 시스템 프록시 설정 상태에서 동작(가능하면)
- [ ] 같은 PC에서 2회 연속 실행, 강제 종료 후 재실행(남은 프로세스·잠긴 파일 없음)
- [ ] exe 폴더를 읽기 전용으로 만들고 실행 → 대체 경로에 결과 생성·경로 표시

**결과·시간**
- [ ] `result.json`이 exe 폴더에 UTF-8(BOM 없음)으로 생성, JSON 파싱·스키마 검증 통과
- [ ] "탐지 시작"~"탐지 완료" 화면 시간 = `meta.elapsed_sec` (±1초)
- [ ] 테스트 사이트(우리가 만든 것, 300페이지 규모)에서 5분 이내, 최대 RAM 사용량 기록
- [ ] 내부 상한(20분) 강제 테스트: 상한 1분으로 줄여 실행 → 부분 결과로 `result.json` 정상 생성
- [ ] 작업 관리자에서 CPU 4코어·RAM 8GB 환경 기준 병렬 수 자동 조정 확인

**AI**
- [ ] `.env` 없음 → AI 꺼짐 표시, 결과 정상
- [ ] `.env`에 잘못된 키 → 폴백, 결과 정상, 오류 안내
- [ ] `.env`에 올바른 키 → 호출 횟수·토큰 표시, 재빌드 없이 키 교체 반영
- [ ] `.env.txt`로 저장한 경우·BOM 있는 경우도 읽힘
- [ ] 로그·결과 파일에 키가 남지 않음

**문서**
- [ ] 사용설명서 첫 장: 결과 파일 경로, SmartScreen 안내, `.env` 변수표(서비스명·모델명·환경변수명), 해시
- [ ] 실행/빌드 매뉴얼: Python 버전, `requirements.txt`(버전 고정), `playwright install chromium --only-shell`, PyInstaller 명령(onedir, `--noupx`, `--version-file`), 빌드 스크립트 한 줄 실행

## 10. 01·02 문서에 대한 정정·보완

| 문서 | 기존 내용 | 정정·보완 |
|---|---|---|
| 01 §5 | Edge(`msedge`) 먼저, 실패 시 Chromium | **번들 Chromium headless shell 먼저, Edge는 폴백.** Edge 정책 `RemoteDebuggingAllowed=0`이면 파이프 제어가 막힘(MS 공식), 버전 불일치·new headless로 더 무거움 |
| 01 §5 | `PLAYWRIGHT_BROWSERS_PATH=0` | 공식 방법이지만 경로 꼬임 사례가 많다. **`executable_path`로 exe 옆 브라우저를 직접 지정**하는 편이 확실. onefile(`-F`, 공식 예시)이 아니라 **onedir** |
| 01 §5 | 결과는 `sys.executable` 폴더 | 맞음. 추가로 `.env`도 같은 기준으로 명시 경로 로딩, 쓰기 실패 시 대체 경로 표시 |
| 01 §5 / GOAL §9 | "PyInstaller exe는 오탐이 잦음 → 백신 검사" | UPX 끔·버전 정보·onedir·VirusTotal·MS 오탐 제출까지 구체화. 미서명 SmartScreen 안내 필요 |
| 01 §4, 02 §8 | "탭 4~8개" | 브라우저 1개 + 컨텍스트 **4~6개**, RAM 기준 자동 조정. 8개는 8GB PC에서 위험 |
| 02 §8 | "분석 스크립트 요청 차단" | 알려진 외부 분석 도메인만. **CSS·일반 JS는 차단 금지**(계산 스타일·JS 삽입 광고 필요) |
| 02 §8 | "정적 HTML 먼저, 렌더링은 분석이 필요한 페이지만" | 숨김 판정은 계산 스타일이 필요하므로 **분석 대상 페이지는 전부 렌더링**. 정적 요청은 링크 수집·중복 제거용, `context.request`로 |
| 02 §1 | "렌더링 끝난 뒤 DOM 분석 (네트워크 유휴 대기)" | Playwright가 `networkidle`을 DISCOURAGED로 표시. `domcontentloaded` + `load` 상한 + DOM 변화 정지 대기로 바꾼다 |
| 02 §8 | 측정 구간 | 브라우저 기동은 "탐지 시작" 전에 끝내 둔다(측정 구간 밖). `result.json` 쓰기 완료 후 "탐지 완료" 표시 |
