## 문제점 (심각도 순)

### P1. 시작 주소가 위험 주소 필터에 걸리면 한 쪽도 점검하지 않는다 — 심각
- 현상: B·C가 0.5초 만에 끝나고 화면에는 "시작 주소를 열지 못했습니다. 주소가 맞는지, 사이트가 켜져 있는지…"가 나온다
- 원인: B 주소의 `vote.php`, C 주소의 `freeboard_writeform`이 `DANGER`(쓰기·삭제·투표 링크 차단 패턴)의 `vote`·`write`에 걸려 `push()`가 시작 주소를 큐에 넣지 않는다. 브라우저로는 둘 다 정상으로 열린다
- 영향: 사용자가 넣은 주소를 조용히 버리고, 안내 문구가 원인과 달라 사용자는 사이트 문제로 오해한다. 게시판 프로그램 이름에 `write`·`update`·`print`가 들어간 공공 사이트는 흔하다

### P2. 게시판 스팸을 "해킹 삽입 의심(심각)"으로 잘못 분류한다 — 심각
- 현상: A의 143묶음 중 68묶음이 "심각 · 해킹 삽입 의심"
- 원인: 해킹 판정 규칙이 "같은 문구가 2개 이상 페이지의 같은 위치"인데, 게시판에서는 정상적으로 이 조건이 생긴다
  - 그누보드 공통 머리의 숨김 제목 `h1#hd_h1`에 글 제목이 들어가고, 같은 글이 목록·보기 화면 등 여러 주소로 열린다
  - 이전/다음 글 링크(`li.btn_prv > a`, `li.btn_next > a`)에 이웃 글 제목이 들어가 82쪽에서 같은 위치·같은 문구로 반복된다
- 영향: 조치 안내가 "KISA 신고, 웹셸 점검, 서버 복구"로 나가서 담당자가 불필요한 침해 대응을 하게 된다. 본심사 "실무 활용성"에서 가장 눈에 띄는 오판이다

### P3. 사이트의 접근성용 숨김 제목을 숨김 광고(OFFSCREEN)로 보고한다 — 높음
- 현상: A에서 `h1#hd_h1` 133건이 OFFSCREEN (`font-size 0px; 글자 박스 없음`)
- 원인: 그누보드 테마는 화면낭독기용으로 페이지 제목을 글자 크기 0으로 숨긴다. 스팸 글이면 그 제목이 광고 문구라서 "숨김 + 광고성" 조건을 만족한다
- 영향: 숨긴 주체가 스패머가 아니라 사이트 템플릿이다. 채점 정답에 없을 가능성이 높아 정확도(35점)를 깎고, 보고서에서 "숨김 광고"로 보여 담당자를 헷갈리게 한다. 같은 광고가 본문(`span.bo_v_tit`)에 보이는 그대로 있어서 숨김 검출로서 가치도 낮다

### P4. 같은 요소를 HOMOGLYPH와 JAMO로 모두 보고한다 — 높음 (결정 필요)
- 현상: A의 변형 검출 229개 요소 전부가 두 기법으로 각각 1건씩 (458건)
- 원인: "ㅋr"(자모 + 라틴 r)은 자모 판정("자모를 조합하면")과 유사 문자 판정("자모 옆 라틴을 한글로 읽으면") 둘 다 걸린다. 규칙상 "한 요소에 기법 2개면 기법마다 1건"이라 형식은 맞다
- 영향: 출제자가 이런 표기를 한 기법으로만 정답 처리하면 나머지 절반이 오탐이 된다. 어느 쪽으로 볼지 기준을 정해야 한다 (research/04 판정 규칙과 대조)

### P5. 숨겨진 "댓글 수정 입력창"을 숨김 광고로 보고하고, 실제로 보이는 댓글은 위치로 잡지 않는다 — 높음
- 현상: D의 24건이 모두 `div.replyCnArea > textarea.textarea` (렌더링 안 됨, display:none)
- 원인: D의 댓글마다 "수정" 버튼을 누르면 펼쳐지는 입력창이 미리 댓글 원문을 담고 숨어 있다. 화면에 보이는 원문(`p.commt_txt`)은 보이는 광고라 4종에 해당하지 않아 빠지고, 숨은 입력창만 남는다
- 영향: 위치가 사용자 화면과 맞지 않는다(담당자가 찾아가면 보이는 댓글이 아니라 숨은 폼). 정답이 "보이는 댓글"을 기준으로 하면 위치가 어긋난다. 같은 패턴(숨은 수정 폼)은 게시판 솔루션에 흔하다

### P6. 전각·가나 섞기와 소프트 하이픈 삽입을 놓친다 — 높음
- 현상: D의 보이는 댓글에서 다음 두 가지가 검출되지 않음
  - `온라인바카라 † く 【￥ bcc777。COM ￥】 ぅ ♪ 네임드사다리토토`: 전각 `￥`, 마침표 대신 `。`(U+3002), 사이사이 일본어 가나 → `textcheck.check()` 결과 HOMOGLYPH 없음
  - `카­지노­커뮤­니티`: 글자 사이 소프트 하이픈(U+00AD, 화면에 안 보임) → 키워드 `카지노`는 찾았지만 `ad: False`, 기법 없음
- 영향: 실제 스팸이 쓰는 회피 기법을 놓친다. 소프트 하이픈은 "보이지 않는 문자 삽입"으로 4종 밖 추가 유형(창의성 20점) 후보이기도 하다

### P7. 같은 canonical 주소로 묶이는 페이지를 반복 방문한다 — 중간
- 현상: E에서 결과 50쪽 중 같은 주소가 8번씩 (`board_vqqG39/1381`, `/1373`, `/1370`, `/1356` 각 8회)
- 원인: 정렬·보기 방식 꼬리표가 다른 주소들이 canonical은 같지만 목록 부분 내용이 달라 내용 해시 중복 제거를 통과한다
- 영향: 3분 예산 대부분을 같은 글에 써서 스팸 게시판(입학 Q&A)의 스팸 글까지 가지 못했다. 같은 검출이 여러 번 나오면 결과는 main에서 합쳐지지만 탐색 시간은 버린다

### P8. XE 게시판의 정렬·보기 꼬리표와 회원 화면을 걸러내지 못한다 — 중간
- 현상: E에서 `sort_index=readed_count|regdate|title`, `order_type=desc`, `listStyle=viewer`, `act=dispMemberLoginForm|SignUpForm|FindAccount`를 각각 방문
- 원인: `NOISE`가 그누보드·전자정부 꼬리표(`sst`, `sod`, `sort`, `order` 등) 중심이라 XE 키를 모른다. 회원 화면은 위험 주소가 아니라서 들어간다
- 영향: P7과 함께 탐색 예산 낭비. XE는 대학·단체 사이트에 많다

### P9. 검출이 많으면 보고서가 지나치게 커지고 캡처가 빠진다 — 중간
- 현상: A의 `report.html` 39.2MB, 143묶음 중 43묶음 "캡처 생략(상한)", 20묶음 "캡처 실패: 요소를 찾지 못함"
- 원인: 캡처 상한(`SHOT_MAX` 100, `SHOT_SEC` 240초)과 묶음당 전·후 2장. 실패 20건은 다시 열었을 때 위치(이전/다음 글 링크 등)가 달라지는 경우로 보임 (원인 미확인)
- 영향: 점검 기록(`records/`)에 보고서 사본이 쌓이면 디스크를 빠르게 쓴다. 40MB HTML은 열기도 느리다. 캡처가 빠진 묶음이 하필 위험도 낮은 순서로 뒤에 몰리는지 확인 필요

### P10. 클릭 탐색이 언어 전환·검색 버튼까지 누른다 — 중간 (확인 필요)
- 현상: E에서 중국어 경고창("找不到相關內容", "請輸入關鍵字"), D·E에서 "검색어를 입력해주시기 바랍니다" 경고창이 반복
- 원인(추정): 클릭 탐색이 언어 선택 버튼을 눌러 세션 언어가 바뀌었고, 빈 검색 버튼도 누른다
- 영향: 세션 언어가 바뀌면 그 뒤 페이지가 다른 언어로 렌더링되어 한글 키워드 판정을 놓칠 수 있다. 실제로 이후 페이지 언어가 바뀌었는지는 아직 확인하지 않았다

### P11. 병렬 수가 1까지 줄어 끝까지 회복하지 못한다 — 낮음 (원인 미확인)
- 현상: A·F에서 "동시 접속을 3개로 → 1개로 줄입니다"
- 원인: 연속 실패의 종류를 기록하지 않아 모른다. 서버 부하일 수도, 특정 페이지 함정일 수도 있다
- 영향: 점검 시간 증가. 실패 원인을 진행 기록에 남겨야 판단할 수 있다

### P12. 이미지 보기 화면을 페이지로 방문한다 — 낮음
- 현상: A에서 `bbs/view_image.php?fn=...jpg`를 페이지처럼 방문 (여러 건)
- 원인: 확장자 검사는 경로만 보는데 이미지 경로가 쿼리 값(`fn=`)에 있다
- 영향: 탐색 예산 소량 낭비
