# 검출 개수(재현율) 탐색 전략: 어떤 사이트가 나와도 모든 페이지와 숨긴 위치에 도달하기

- 작성일: 2026-10-14
- 담당 평가 항목: 적격평가 **정답 검출 개수 (45점)**. 정답 하위 URL과 검출 항목을 찾아낸 개수
- 방법: 공식 문서와 오픈소스 소스코드 확인, 실제 공공 누리집 가볍게 열람(curl 3회), **Playwright 1.64(Python) + 로컬 2-origin 테스트 사이트로 직접 실험**(이하 "직접 확인")

## 핵심 결론

1. **모든 페이지를 브라우저로 렌더링해야 한다.** TRANSPARENT·OFFSCREEN은 계산된 스타일이 있어야 판정할 수 있으므로 정적 HTML만 받고 끝내는 페이지가 있으면 안 된다. 정적 요청은 robots/sitemap/JS 파일 수집에만 쓴다. 속도는 탭 병렬로 확보한다(200쪽 × 약 1초 ÷ 6탭 ≈ 1분 이하).
2. **링크 발견은 5단계로 한다.** ① DOM의 `href`·`src`·`action`, ② 주석·`<script>`·속성 문자열 속 URL, ③ robots.txt·sitemap, ④ `onclick`·`javascript:`·POST 폼을 **클릭해서 가로챈 이동 요청**, ⑤ 더보기·탭·댓글 페이지 버튼을 클릭한 뒤 바뀐 DOM. 전자정부 표준프레임워크 공통컴포넌트는 **상세 페이지와 목록 페이지 이동이 모두 POST**이므로 ④가 없으면 게시글을 하나도 못 연다.
3. **iframe은 `page.frames`로 거의 다 잡히지만 함정이 3개 있다(직접 확인).** cross-origin, `srcdoc`, JS로 채운 `about:blank`, `display:none`, 동적 생성, closed Shadow DOM 안의 iframe은 모두 `page.frames`에 나오고 `evaluate`도 된다. 함정 ① `loading="lazy"` iframe은 스크롤 전에는 URL이 빈 문자열이고 `evaluate`가 **무한 대기**한다. ② 리다이렉트된 iframe은 `frame.url`과 `src` 속성이 다르다. location에는 `src` 속성을 절대 주소로 바꿔 쓴다. ③ `srcdoc` iframe은 `src`가 없다.
4. **Shadow DOM:** Playwright 로케이터는 open shadow root를 관통하지만 `document.querySelectorAll`과 XPath는 관통하지 못한다. closed shadow root는 `add_init_script`로 `attachShadow`의 mode를 open으로 강제하면 열린다(직접 확인).
5. **범위와 정규화:** 같은 등록 도메인(`*.기관.go.kr`; `go.kr`은 Public Suffix List에 있다)으로 범위를 정한다. 중복 판정 키는 모집요강 12쪽 규칙(스킴·끝 `/`·`#` 무시, 쿼리 순서 무시)과 똑같이 만든다. 무한 URL은 "경로 + 파라미터 이름 집합" 패턴마다 상한을 두어 막는다. 넘치는 URL을 아예 막지 않고 BFS 큐 뒤로 미룬다. 우선순위는 게시판 상세 > 목록 > 일반 페이지 순이다.

### 공공 게시판에서 반드시 막을 "쓰기·파괴" 동작

## 2. 크롤러가 놓치기 쉬운 경로

| 구조 | 왜 놓치나 | 어떻게 도달하나 (구현) | 근거 |
|---|---|---|---|
| `robots.txt`의 `Disallow`·`Sitemap:` | 메뉴에 링크가 없다 | 시작할 때 `/robots.txt`를 받아 `Sitemap:` 줄과 `Disallow/Allow` 경로를 **시드로** 넣는다. 평가 사이트는 탐지가 목적이므로 Disallow는 "숨은 경로 힌트"로 쓴다 | [sitemaps.org](https://www.sitemaps.org/protocol.html): `Sitemap:` 지시자는 user-agent와 무관. korea.kr robots.txt에 `Sitemap: …/sitemapindex.xml` 있음(**직접 확인**) |
| `sitemap.xml`, sitemap index, `.xml.gz` | robots에 없으면 추측해야 한다 | `/sitemap.xml`, `/sitemap_index.xml`, `/sitemapindex.xml`, `/wp-sitemap.xml`를 시도하고, index는 재귀로 펼치며 gzip을 해제한다. 파일당 최대 50,000 URL | [sitemaps.org](https://www.sitemaps.org/protocol.html). mois.go.kr는 sitemap 없음(404, **직접 확인**)이므로 없을 때를 정상으로 처리 |
| 숨김 링크(`display:none`, 0px, 화면 밖 `<a>`) | "보이는 링크만 클릭"하는 크롤러는 놓친다 | 링크 수집은 **가시성과 무관하게** DOM 전체의 `a[href]`, `area[href]`, `link[href]`, `form[action]`, `iframe/frame[src]`, `[data-href]`, `[data-url]`, `meta[http-equiv=refresh]`에서 한다 | 아시아투데이 2026-05-28(폐기 게시판), 01 문서 §4 |
| HTML 주석 속 URL | DOM 트리 순회에서 빠진다 | `TreeWalker(NodeFilter.SHOW_COMMENT)`로 주석을 모아 URL 정규식(절대 `https?://…` + 상대 `/…\.(do|php|html|jsp|asp)…`)을 적용한다 | [jsluice](https://github.com/BishopFox/jsluice)(JS 문자열 URL 추출), 02 문서 §1 |
| JS 문자열 속 URL (`location.href='/view?id='+n`, `var u="/old/board"`) | 실행하지 않으면 링크가 아니다 | 인라인 `<script>`와 같은 도메인 `.js`의 문자열 리터럴에서 경로처럼 생긴 것을 추출한다. 동적 조합(`'+n`)은 ④ 클릭 가로채기로 보완한다 | Katana `-jc`/`-jsl` 기능([katana](https://github.com/projectdiscovery/katana)) |
| `onclick`, `href="javascript:…"`, `href="#"`, 클릭되는 `div/tr` | href가 없다 | §3-4 "클릭 + 네비게이션 가로채기". 후보는 `[onclick]`, `a[href^=javascript]`, `a[href="#"]`, `role=link/button`, `cursor:pointer`인 요소 | 전자정부 소스, Crawlee `enqueueLinksByClickingElements`([문서](https://crawlee.dev/js/api/playwright-crawler/namespace/playwrightClickElements)). **직접 확인**: `fn_egov…` → `('POST', '/view.html', 'nttId=130155')`, `javascript:goView(77)` → `('GET', '/view.html?id=77')` 포착 |
| POST 폼으로만 열리는 상세·목록 | URL이 모두 같다(`selectArticleDetail.do`) | 큐 항목을 `(method, url, body)`로 저장하고, 중복 키에 body를 포함한다. 결과 `url` 필드 표기는 §4의 "POST 페이지 URL" 참고 | 전자정부 컨트롤러 `@PostMapping`(소스 직접 확인) |
| AJAX 댓글, "더보기", 댓글 페이지 버튼 | 초기 HTML/DOM에 없다 | 렌더링 후 `더보기|more|댓글|이전|다음|[0-9]+` 버튼과 `aria-controls`·`role=tab` 요소를 클릭하고, DOM이 바뀌지 않을 때까지(최대 N회) 반복한 뒤 분석한다. 클릭 중에도 네비게이션 가로채기를 켜 둔다 | **직접 확인**: `#more` 클릭 → `fetch('/cmt.html')` 결과가 `#cmts`에 삽입됨 |
| 무한 스크롤 | 스크롤해야 로딩된다 | `scrollTo(0, scrollHeight)`를 높이가 그대로일 때까지 최대 5회 반복한다. lazy iframe도 이때 로드된다 | 아래 iframe 항목 |
| `target=_blank`, `window.open` 팝업 | 새 탭이 열려 원래 페이지 이벤트에 안 잡힌다 | `context.on("page")`로 새 페이지 URL을 큐에 넣고 탭은 바로 닫는다 | Playwright `expect_popup`/`expect_page`([Page API](https://playwright.dev/python/docs/api/class-page)). **직접 확인**: `window.open('/list.html')` URL 포착 |
| iframe: 같은 출처 / cross-origin / 중첩 | DOM `querySelectorAll`은 프레임 안으로 못 들어간다 | `page.frames`(또는 `main_frame.child_frames` 재귀)를 돌며 각 프레임에서 분석 스크립트를 `evaluate`한다. 경로는 `frame.parent_frame`을 거슬러 올라가 `iframe[src="절대URL"] >>> …`로 만든다 | [Frame API](https://playwright.dev/python/docs/api/class-frame). **직접 확인**: 127.0.0.1:8002 cross-origin iframe 안의 iframe(다시 localhost)까지 `evaluate` 성공 |
| `srcdoc` iframe | `src`가 없고 `frame.url == "about:srcdoc"`이다 | `page.frames`에 나오며 `evaluate`도 된다. location은 `iframe[src=…]`로 쓸 수 없으므로 `iframe:nth-of-type(k)` 등 **유일한 선택자**로 쓴다(테스트 사이트로 규칙 확정) | **직접 확인**, [MDN iframe](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe)(srcdoc이 src보다 우선) |
| JS로 `document.write`한 `about:blank` iframe | 네트워크 요청이 없다 | `page.frames`에 `about:blank`로 나오고 내용도 읽힌다 | **직접 확인** |
| `sandbox=""` iframe | 스크립트가 막혀 분석이 안 될 것 같다 | Playwright `evaluate`는 sandbox와 관계없이 동작했다 | **직접 확인** |
| `display:none` / 0px iframe | 보이지 않는다 | 로딩은 정상이며 `page.frames`에 포함된다 | **직접 확인** |
| JS로 나중에 만든 iframe | load 이벤트 이후에 생긴다 | DOM 안정 대기(아래 §3-3) 후 `page.frames`를 다시 읽는다 | **직접 확인**: 300ms 후 생성된 `/dyn.html` 포착 |
| `loading="lazy"` iframe (화면 아래) | **스크롤 전에는 URL이 `''`이고 `evaluate`가 무한 대기한다** | ① 분석 전에 끝까지 스크롤한다. 또는 ② `add_init_script`로 `loading` 속성을 지운다. 그리고 모든 프레임 `evaluate`에 `asyncio.wait_for(…, 3~5초)` 타임아웃을 건다 | **직접 확인**(스크롤 후 `/lazy.html` 로드됨). [MDN](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe): "Loading is only deferred when JavaScript is enabled" |
| 리다이렉트되는 iframe | `frame.url`이 바뀐다 | location의 `src`는 **`frame_element()`의 `src` 속성**을 절대 주소로 바꿔 쓴다(DOM `iframe.src` 프로퍼티가 절대 URL을 준다). 페이지를 찾을 때는 `frame.url`도 큐에 넣는다 | **직접 확인**: `src="/redir?a=1"` → `frame.url = /hidden.html` |
| open Shadow DOM | `document.querySelectorAll`, XPath는 관통하지 못한다 | 분석 JS가 `el.shadowRoot`를 재귀로 순회한다(링크 수집 포함). Playwright CSS 로케이터는 자동으로 관통한다 | [Playwright locators](https://playwright.dev/python/docs/locators): "Locating by XPath does not pierce shadow roots", "Closed-mode shadow roots are not supported". **직접 확인**: qsa 0개, locator 1개 |
| closed Shadow DOM | `shadowRoot`가 `null`이다 | `context.add_init_script("Element.prototype.attachShadow = …{...init, mode:'open'}")`로 강제로 연다. 문서 생성 직후, 페이지 스크립트보다 먼저 실행된다 | **직접 확인**: 강제 전에는 텍스트·링크 0개, 강제 후 `CLOSED 토토`와 `/shadow-closed.html` 포착. [add_init_script](https://playwright.dev/python/docs/api/class-page) |
| closed Shadow DOM 안의 iframe | DOM 순회로 못 찾는다 | `page.frames`는 브라우저 프레임 트리라서 나온다 | **직접 확인** |
| HTTP 30x / meta refresh / JS 리다이렉트 | 시작 URL과 최종 URL이 다르다 | `response.url`(최종)을 페이지 URL로 기록하고 원래 URL도 방문 완료로 표시한다. meta refresh의 URL은 링크로도 수집한다 | 02 문서 §7(최종 URL) |
| 해시 라우팅 SPA (`#/board/1`) | 채점이 `#` 이하를 비교하지 않으므로 **모든 화면이 같은 URL**이 된다 | 해시 링크를 클릭하거나 `location.hash`를 설정해 화면별로 렌더링하고 분석한다. 결과 `url`은 `#` 앞까지만 같고 location으로 구분된다. 같은 url+location+technique가 겹치면 1건으로 통합된다 | 모집요강 12쪽 |
| `history.pushState` SPA | 링크 href는 정상이지만 서버 응답이 같은 셸이다 | `goto` 후 렌더링하면 된다. 클릭 가로채기에는 네비게이션 요청이 안 생기므로 클릭 전후 `page.url` 변화도 기록한다 | 일반 지식 |
| 링크가 전혀 없는 옛 게시판·글 (`?id=` 사이 공백) | 어디에도 링크가 없다 | 마지막 단계(시간이 남을 때만): 같은 패턴에서 관측된 숫자 ID 사이를 제한적으로 탐색한다(패턴당 ≤30회, 404·빈 페이지면 중단) | 아시아투데이 2026-05-28 사례. **주의**: 실제 출제 여부는 불확실하므로 우선순위를 최하로 둔다 |
| 문자 인코딩 EUC-KR 페이지 | 정적 요청에서 한글 URL·텍스트가 깨진다 | 렌더링은 브라우저가 처리한다. 정적 요청(robots/JS)은 `Content-Type` charset, 그다음 `<meta charset>` 순으로 디코딩한다 | 일반 지식 |

## 3. Playwright(Python) 구현 방법

### 3-1. 컨텍스트 준비

```python
ctx = await browser.new_context(ignore_https_errors=True, service_workers="block")
await ctx.add_init_script(FORCE_OPEN_SHADOW)   # closed → open (직접 확인)
await ctx.add_init_script(REMOVE_LAZY)          # iframe/img loading=lazy 무력화(선택)
ctx.on("page", on_popup)                        # window.open / target=_blank URL 수집 후 close
await ctx.route("**/*", block_heavy)            # image/font/media 차단(속도)
```
- `ignore_https_errors`: 테스트 서버가 자체 서명 인증서일 수 있다.
- 대화상자(`alert`/`confirm`)는 리스너가 없으면 Playwright가 자동으로 닫는다([Playwright Dialogs](https://playwright.dev/python/docs/dialogs): "By default, dialogs are auto-dismissed by Playwright"). `confirm("삭제?")` 같은 위험한 확인창도 닫혀서 진행되지 않으므로 안전하다.

### 3-2. 페이지 하나 처리 순서

1. `goto(url, wait_until="load", timeout=15s)`. POST 항목은 같은 페이지에서 폼을 재현하거나 `route`로 method/body를 바꿔 연다.
2. **안정 대기**: `networkidle`은 쓰지 않는다. 공식 문서가 "DISCOURAGED"로 표시했고([Page.goto](https://playwright.dev/python/docs/api/class-page)), 공공 누리집은 통계·채팅 위젯 때문에 유휴 상태가 오지 않을 수 있다. 대신 `load` 후 **MutationObserver로 300~500ms 동안 DOM 변화가 없을 때까지**(최대 3초) 기다린다.
3. 끝까지 스크롤한다(최대 5회). lazy iframe과 무한 스크롤을 불러온다.
4. 더보기·댓글 페이지·탭 클릭(안전 단어 필터, 최대 10회). 클릭할 때마다 2번 대기를 반복한다.
5. `page.frames` 전체에서 **링크 수집 JS와 탐지 JS를 함께** 실행한다(`asyncio.wait_for` 3~5초, 실패한 프레임은 건너뛴다). 이때 shadowRoot를 재귀로 순회하고 주석·스크립트 문자열도 본다.
6. 클릭 후보(`onclick`, `javascript:`, `#`)는 **별도 단계**로 처리한다(아래 3-4).

### 3-3. iframe location 경로 만들기

```python
async def frame_prefix(frame):
    parts = []
    while frame.parent_frame:
        el = await frame.frame_element()
        src = await el.evaluate("e => e.getAttribute('src') ? e.src : null")  # 절대 URL
        parts.append(f'iframe[src="{src}"]' if src else await unique_selector(el))  # srcdoc 등
        frame = frame.parent_frame
    return " >>> ".join(reversed(parts))
```
- 같은 `src`의 iframe이 한 페이지에 2개 있으면 `iframe[src=…]`가 2개를 가리키게 되어 오답이다. 이때는 상위 경로나 `:nth-of-type`을 붙인다. 이 규칙은 테스트 사이트로 확정한다.

### 3-4. 클릭으로 링크 발견 (직접 확인한 방식)

```python
caught = []
async def intercept(route):
    r = route.request
    if r.is_navigation_request() and r.frame == page.main_frame and norm(r.url) != norm(cur):
        caught.append((r.method, r.url, r.post_data)); await route.abort()
    else:
        await route.continue_()
await page.route("**/*", intercept)
for cand in candidates:                       # 후보마다
    await page.goto(cur)                      # abort 후 페이지가 chrome-error로 바뀌므로 다시 연다
    await page.locator(cand).click(timeout=3000, no_wait_after=True)
    await page.wait_for_timeout(300)          # setTimeout 이동 대비 (Crawlee 기본 1초, 최대 5초)
```
- **실험 결과**: `route.fulfill(status=204)`로 이동을 막으면 페이지는 남지만, 그 뒤로 로케이터·클릭이 **멈춰서 쓸 수 없었다**. `abort` 후 매번 다시 `goto`하는 방식이 안정적이었다.
- 비용을 줄이려면 같은 함수명 패턴(`fn_egov_inquire_articledetail('A','1')`, `…('A','2')`)은 **1개만 클릭해서 템플릿을 학습**한다. 즉 POST body의 어느 값이 인자와 대응하는지 파악한 뒤, 나머지는 클릭 없이 `(method, url, body)`를 만들어 낸다. 게시판 목록 1쪽당 클릭이 10회에서 1회로 준다.
- iframe 안의 onclick도 같은 방식으로 처리한다(`r.frame == 해당 frame`).

### 3-5. 병렬과 시간 관리

- `asyncio` + 탭 4~8개 워커 + 공유 우선순위 큐(§4-3).
- 페이지당 하드 타임아웃 20~30초, 프레임 evaluate 5초.
- **소프트 데드라인 20분**: 새 페이지 방문을 멈추고 결과를 쓴다. **하드 데드라인 25분**: 진행 중인 작업을 취소하고 즉시 `result.json`을 쓴다. 중간 결과도 주기적으로 저장한다.

## 4. 크롤링 범위·정규화·상한·우선순위

### 4-1. 범위

| 경우 | 규칙 | 근거 |
|---|---|---|
| 같은 호스트 | 포함 | 기본 |
| 서브도메인(`board.기관.go.kr`) | 등록 도메인이 같으면 포함한다. `go.kr`, `or.kr`, `seoul.kr` 등은 PSL에 공개 접미사로 등록되어 있으므로 `tldextract` 같은 PSL 기반 계산을 쓴다(`example.go.kr`이 등록 도메인) | [Public Suffix List](https://publicsuffix.org/list/public_suffix_list.dat)(go.kr 등재, **직접 확인**), Crawlee `same-domain` 전략, Katana `-fs rdn` |
| 진입 URL이 하위 경로(`/siteA/`)인 경우 | 같은 호스트 전체를 허용하되 경로 접두사가 같은 URL을 먼저 처리한다. 평가 서버에 다른 사이트가 함께 있을 수 있으므로 접두사 밖 URL은 **접두사 안 페이지에서 링크된 경우만** 따라간다 | 모집요강 "입력받은 URL을 시작으로 하위 페이지" |
| 외부 도메인 | 방문하지 않는다. 단, **페이지 안에 삽입된 외부 iframe은 분석한다**(location은 부모 페이지 기준) | 모집요강 붙임1 "페이지 내 삽입된 iframe 내부 요소" |
| iframe src 페이지 자체(같은 도메인) | 모집요강 예시에서 `/widget/notice`는 iframe으로만 등장하고, url은 부모 페이지(`view?id=1180`)다. 단독 페이지로도 방문하면 **같은 광고가 url만 다른 별건으로 하나 더 나와 정확도가 떨어질 수 있다** → 기본값은 "iframe으로만 참조되면 단독으로 출력하지 않음". `<a>`로도 링크되어 있을 때만 단독 페이지로 분석한다. **테스트 사이트와 Q&A로 확정할 것** | 모집요강 13쪽 예시 f_004 |
| 비HTML(`.pdf`, `.hwp`, `.zip`, 이미지) | 방문하지 않는다(`Content-Type` 확인, 확장자로 선필터) | 4종 탐지 대상이 HTML 요소 |

### 4-2. URL 정규화 (모집요강 12쪽과 1:1 대응)

| 단계 | 처리 | 이유 |
|---|---|---|
| 1 | `#` 이하 제거 | 채점이 비교하지 않음 |
| 2 | 스킴 무시(키에서는 `//host/...`) | http/https 차이 무시 |
| 3 | 호스트 소문자, 기본 포트(80/443) 제거 | 표준 |
| 4 | 경로 끝 `/` 제거(루트 제외) | 끝 `/` 차이 무시 |
| 5 | `;jsessionid=…` 같은 경로 파라미터 제거 | mois.go.kr href 실사례(**직접 확인**) |
| 6 | 쿼리를 `parse_qsl(keep_blank_values=True)`로 파싱 → 정렬 → 다시 인코딩. 퍼센트 인코딩을 통일하고 `&amp;`를 해제한다 | 순서만 다르면 같은 페이지, 값이 다르면 다른 페이지 |
| 7 | 빈 값 파라미터(`searchCnd=&searchWrd=`)는 **키에서는 유지**한다(채점 규칙상 지우면 다른 페이지가 될 수 있다). 대신 §4-4의 콘텐츠 중복 검사로 이중 방문을 막는다 | 보수적 해석 |
| 출력 | `url` 필드에는 정규화 키가 아니라 **실제 방문한 최종 URL(# 제거, jsessionid 제거)**을 쓴다 | 채점은 자체 정규화를 하므로 원형이 안전하다 |

**POST 페이지 URL**: 전자정부 공통컴포넌트처럼 상세가 POST이면 모든 글이 `…/selectArticleDetail.do` 한 URL이 된다. 채점은 url+location+technique로 1건을 판정하므로 여러 글의 같은 위치 광고가 1건으로 합쳐질 수 있다. 대응 방안은 다음과 같다. ① 같은 파라미터로 **GET 요청을 시도해 같은 내용이 나오면** `action?bbsId=…&nttId=…` 형식으로 출력한다(많은 기관 커스텀 구현은 GET도 받는다: mois.go.kr에서 href GET 사용, 직접 확인). ② GET이 안 되면 action URL 그대로 출력한다. (판단 근거는 §8)

### 4-3. 우선순위 (BFS + 가중치)

| 순위 | 대상 | 이유 |
|---|---|---|
| 0 | 진입 URL, robots/sitemap 시드 | 출발점 |
| 1 | 게시글 상세(파라미터 이름이 `id|wr_id|nttId|document_srl|no|idx|seq|p|articleNo` 등이거나, 경로에 `view|read|detail|article`) | 광고가 가장 많이 숨는 곳(본문·댓글). 모집요강 예시도 `view?id=` |
| 2 | 게시판 목록 1쪽과 이후 쪽(`page|pageIndex|cpage|pageNo`) | 상세 링크의 공급원 |
| 3 | 일반 메뉴 페이지(깊이 ≤ 3) | 공통 영역·위젯 |
| 4 | 숨김 링크·주석·JS 문자열에서만 발견된 URL | 출제 가능성은 높지만 수가 적다. **순위가 낮아도 반드시 방문한다**(상한 밖으로 빼지 않는다) |
| 5 | 상한을 넘은 패턴의 나머지 URL, ID 탐색 | 시간이 남을 때만 |

- 순수 DFS를 쓰면 한 게시판의 수백 쪽에 시간을 다 쓴다. BFS를 기본으로 하되 1~2순위를 먼저 꺼내는 **우선순위 BFS**로 한다(Katana `-s breadth-first` 참고).

### 4-4. 무한 URL·중복 방지 상한

| 함정 | 판별 | 상한(제안) |
|---|---|---|
| 달력(`year=&month=`, `date=`, `/2026/10/`) | 파라미터 이름이나 값이 날짜 형태 | 패턴당 24개 |
| 정렬·검색·필터(`sst, sod, sfl, stx, sca, searchCnd, searchWrd, order, sort`) | 파라미터 이름 | 이 파라미터만 다른 URL은 **값 조합당 1개**만 방문 |
| 페이지네이션 | `page|pageIndex|cpage` | 게시판당 50쪽(테스트 사이트 규모상 충분). 새 상세 링크가 0개인 쪽이 2번 연속 나오면 중단 |
| 같은 패턴(경로 + 정렬된 파라미터 이름 집합) | 서명 계산 | 패턴당 300개 |
| 콘텐츠 중복(그누보드 `&page=` 꼬리표, 세션 파라미터) | 본문 텍스트 해시(SimHash 등)가 같은 페이지 | 두 번째부터는 링크만 수집하고 탐지는 생략 → **대표 URL은 쿼리가 가장 짧은 것** |
| 전체 | 페이지 수 | 2,000쪽 또는 소프트 데드라인 |

| `loading="lazy"` iframe(5000px 아래) | 스크롤 전 `url=''`, **`evaluate` 무한 대기(테스트 전체가 멈춤)**. 스크롤 후 로드됨 |
| 302 리다이렉트 iframe | `frame.url = /hidden.html`, `src` 속성 = `/redir?a=1` |
| open shadow | `querySelectorAll('.ad')` 0개, `locator('.ad')` 1개 |
| closed shadow | 기본 0개 → `attachShadow` mode 강제 후 텍스트·링크 모두 포착. 안에 있는 iframe은 강제 없이도 `page.frames`에 나옴 |
| onclick → POST 폼 / `javascript:` → `location.href` | `route` + `is_navigation_request()`로 `(POST, /view.html, nttId=130155)`, `(GET, /view.html?id=77)` 포착. `abort`하면 페이지가 `chrome-error://`로 바뀌므로 다시 `goto` 필요. `fulfill(204)`은 이후 조작이 멈춤 |
| `window.open` | `context.expect_page`로 새 페이지 URL 포착 |
| AJAX 더보기 | 클릭 후 500ms 안에 `fetch` 결과가 DOM에 삽입됨 |

## 7. 테스트 사이트(todo/02)에 넣을 탐색 시나리오 체크리스트

각 항목에 광고(4종 중 하나)를 1개 이상 숨기고 정답 json에 넣는다. 크롤러가 해당 URL을 방문하지 못하면 놓치게 된다.

**링크 구조**
- [ ] 일반 `<a href>` 메뉴 → 하위 페이지(깊이 3 이상)
- [ ] 게시판 목록 1쪽, **3쪽 이상**(페이지 번호 링크)
- [ ] 상세 `view?id=N`. 쿼리 순서만 다른 링크 2개(같은 페이지로 처리되는지 확인)
- [ ] 상세 링크에 목록 상태 꼬리표(`&page=2`)가 붙는 그누보드식 링크 → 중복 처리 확인
- [ ] `href="javascript:void(0)" onclick="fn_view('123')"` → **GET** 이동
- [ ] `onclick` → hidden 폼 **POST** 이동(전자정부식 상세), POST로만 열리는 목록 2쪽
- [ ] `<tr onclick="location.href=…">`처럼 a가 아닌 클릭 요소
- [ ] `target=_blank` 링크, `window.open` 팝업
- [ ] `setTimeout` 뒤 JS 리다이렉트, `<meta http-equiv=refresh>`, HTTP 302
- [ ] 해시 라우팅 화면(`#/notice/1`) 1개
- [ ] 경로에 `;jsessionid=…`가 붙은 링크

**숨은 경로**
- [ ] `display:none` 링크로만 연결된 옛 게시판
- [ ] HTML 주석 속 URL로만 알 수 있는 페이지
- [ ] 인라인 JS 문자열(`var old = "/old/board"`)로만 알 수 있는 페이지
- [ ] `robots.txt` `Disallow:` 경로로만 알 수 있는 페이지
- [ ] `sitemap.xml`(index → 하위 sitemap)로만 알 수 있는 페이지
- [ ] 어디에도 링크가 없고 ID 사이 공백만 있는 글(선택, 최하 우선순위 검증용)

**동적 콘텐츠**
- [ ] AJAX로 불러오는 댓글(페이지 로드 직후 `fetch`)
- [ ] "댓글 더보기" 버튼을 눌러야 나오는 댓글, 댓글 2쪽(`cpage=2`)
- [ ] 무한 스크롤 목록
- [ ] 탭을 클릭하면 AJAX로 채워지는 영역
- [ ] load 2초 뒤 JS가 삽입하는 광고

**iframe·Shadow DOM**
- [ ] 같은 출처 iframe(상대 경로 src → location은 절대 주소)
- [ ] 다른 포트/호스트로 만든 cross-origin iframe
- [ ] 2단 이상 중첩 iframe(`>>>` 반복)
- [ ] `srcdoc` iframe, JS로 채운 `about:blank` iframe
- [ ] `display:none`/0px iframe
- [ ] `loading="lazy"` iframe을 페이지 맨 아래에 배치
- [ ] 302로 리다이렉트되는 iframe src
- [ ] 같은 src의 iframe 2개(선택자 유일성 검증)
- [ ] JS로 나중에 생성되는 iframe
- [ ] open Shadow DOM 안의 광고, closed Shadow DOM 안의 광고와 링크

**함정(방문하면 안 되거나 상한 확인용)**
- [ ] 달력 페이지(다음 달 링크가 무한히 이어짐) → 상한 내에서 끝나는지
- [ ] 정렬·검색 파라미터 조합 링크 → 폭증하지 않는지
- [ ] "삭제" 링크/버튼(누르면 페이지가 사라지게 구현) → 크롤 후에도 남아 있는지
- [ ] 외부 도메인 링크 → 방문하지 않는지
- [ ] `.pdf`/`.hwp` 링크 → 방문하지 않는지
- [ ] `confirm()`·`alert()`가 뜨는 버튼 → 멈추지 않는지
- [ ] 같은 도메인 iframe 전용 위젯(`/widget/notice`) → 단독 페이지 중복 출력 정책 확인
- [ ] EUC-KR 인코딩 페이지 1개
- [ ] 전체 페이지 200개 이상 규모 → 소요 시간 측정(목표 5분 이내)

## 8. 애매한 부분에 대한 우리 판단 (재현율 관련)

평가 사이트의 구성은 물어볼 수 없다. 모집요강 문구와 예시에 가장 가깝게 판단하고 테스트로 고정한다.

| 애매한 부분 | 판단 | 근거 |
|---|---|---|
| POST로만 열리는 페이지의 `url` | 같은 파라미터로 GET 요청이 같은 글을 돌려주면 **GET URL(파라미터 포함)**을 쓴다. 안 되면 브라우저 주소창에 보이는 URL을 쓴다 | 채점은 쿼리 값으로 페이지를 구분하고(12쪽), 예시 정답이 모두 GET 형식(`view?id=1024`)이다 |
| 같은 도메인 iframe의 src 페이지를 단독으로도 출력하나 | **출력하지 않는다.** iframe 안의 항목은 상위 페이지 url + `iframe[src] >>>` location으로 1번만 낸다 | 예시 정답에서 `/widget/notice`는 iframe으로만 나오고 url은 상위 페이지(`view?id=1180`)다 |
| 탐색 범위 | 진입 URL과 **같은 등록 도메인**의 페이지 + 그 페이지에 들어 있는 **모든 iframe**(다른 도메인 포함) | "입력받은 URL을 시작으로 하위 페이지 … iframe 내부"(5쪽) |
| 공통 영역(모든 페이지의 푸터 등)에 숨긴 광고 | **페이지마다 1건**씩 낸다 | 검출 1건의 단위가 url+location+technique(10쪽) |
