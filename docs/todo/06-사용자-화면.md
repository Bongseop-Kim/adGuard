- 원칙: 심사위원이 실제로 여는 건 보고서 한 장이다. 기능 수보다 완성도. 번호는 research/06 §3-2
- 만드는 것
  - [ ] R1 시작 화면 (URL 1개 + "탐지 시작", 옵션 접기)
  - [ ] R2 진행 상황 ("탐지 완료" 명확히, 중단해도 결과 저장)
  - [ ] R3 요약 대시보드 (위험도 3단계 심각/위험/참고, 기법별 개수)
  - [ ] R4 검출 목록: **지문 1행 + 영향 URL N개 + 최초 발견일** 묶음이 기본 보기 (research/10 §1-2)
  - [ ] R5 근거 상세: 맨 위에 규칙 신호로 만든 한 줄 요약(토큰 0), 원문·정규화 하이라이트·계산된 스타일·HTML 스니펫·선택자 복사 (research/10 §1-3)
  - [ ] R6 숨김 드러내기 미리보기: `page.screenshot(clip=부모 영역, style=드러내는 CSS)`, 개인정보는 `mask` (research/10 §1-4)
  - [ ] R7 조치 안내: 유형별 고정 문구 (게시물형 / 해킹 삽입형 / 검색엔진 흔적 / ISAP)
  - [ ] R9 내보내기: 단일 HTML 보고서(JSON 내장 + 바닐라 JS 렌더러, 앱 화면과 공용, 원문은 `textContent`만, JSON의 `<` 이스케이프) + UTF-8 BOM CSV (research/10 §1-5)
  - [ ] R14 원인 유형 자동 구분 (같은 지문이 여러 페이지 → 해킹 삽입 의심)
