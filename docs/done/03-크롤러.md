## 결정

- 우선순위 BFS(상세 > 목록 > 일반, 같은 순위는 깊이), 브라우저 1개 + 컨텍스트 `min(6, CPU)`, 전체 시간 제한 기본 20분(넘으면 새 페이지를 멈추고 30초 뒤 강제 종료)
- 페이지 처리 순서: 열기 → `load`(≤5초) → DOM 변화 300ms 없음 + 3초 이하 `setTimeout` 대기 없음(≤3초) → 프레임 `load`(≤3초) → 내용 중복 확인 → **펼치기** → 링크 수집 → `analyze` → **클릭으로 링크 발견**. `networkidle` 안 씀
- 펼치기: 보이고 다른 주소 href가 없는 "더보기·펼치기·전체보기·댓글 보기" 류를 내용이 안 늘 때까지(최대 5회, 회당 10개) 누른다. 누른 게 실제로 이동이면 링크로만 쓰고 펼치기를 멈춘다
- 클릭으로 링크 발견: **모든 프레임**의 onclick·`javascript:`를 함수 이름마다 눌러 상위 페이지 이동 요청(POST 본문 포함)을 가로채고, 같은 함수의 나머지는 인자 치환. 이동이 잡힌 것만 템플릿으로 캐시하고, 안 잡히면 그 페이지에서 2개까지 눌러 본다. iframe 자체 이동은 막고 수집하지 않는다
- 외부 JS: 같은 도메인 `script[src]`를 파일마다 1번 받아 따옴표 문자열 속 경로를 수집
- 위험 동작 차단: URL·onclick 코드는 영어 토큰(`delete|write|logout|print…`), 버튼 글자는 **이름 전체가** 위험 단어일 때만(`삭제`, `신고하기` 등). 부분 일치로 막으면 "전입신고 안내", "주민등록", "추천 도서" 같은 정상 메뉴가 빠진다(S4에서 실제로 걸림)
- lazy iframe은 init script가 `loading`을 `eager`로 바꿔 스크롤 없이 로드. closed Shadow DOM은 init script로 open
- URL: `#`·`;jsessionid` 제거, 정렬·검색 꼬리표(`sca, sfl, stx, sst, sod, search*`, `sort` 등) 제거, 글 ID(`id, wr_id, nttId…`)가 있으면 쪽번호(`page, pageIndex…`) 제거. `cpage`(댓글 쪽)는 유지. `<link rel=canonical>`이 있으면 그 URL로 출력. 내용(`textContent`)이 같으면 1번만, 대표 URL은 짧은 것
- POST: 같은 파라미터의 GET(빈 값 제외)을 먼저 열고, 실패할 때만 POST로 열어 action URL로 출력
- iframe src 페이지는 따로 큐에 넣지 않는다 (iframe 안 항목은 상위 페이지 url로, research/03 §8). iframe 안의 링크는 수집한다
- 이미지 등 리소스 차단은 하지 않음 (레이아웃을 실제와 같게). 가로채기 route는 펼치기·클릭 단계에만 건다

## 고친 것

- 크롤러 경합: 이동을 abort하면 Chromium이 `chrome-error://`로 넘어가는데, 바로 다시 연 `goto`가 그 이동에 끊겨("interrupted by another navigation") 해당 목록 페이지가 통째로 실패했다. 부하가 있을 때만 생겨 S2·S3에서 간헐적으로 게시판 전체(최대 48건)가 빠졌다 → 다시 열기를 1번 재시도
- 템플릿: 첫 클릭에서 이동을 못 잡으면 그 함수를 "이동 없음"으로 영구 캐시하던 것을 성공한 것만 캐시하도록
- eval S2: `serve.py`에 `if __name__ == "__main__": main()`이 없어 서버가 뜨지 않았다 → 추가
- eval S2: 정답 a_021의 url이 리다이렉트 전 주소(`/minwon/apply`)였다. 자기 note("최종 URL 기준")·F10·S3 #28과 어긋나 최종 URL `/minwon/apply-notice.html`로 고침
- eval 추가: S4-dynamic(P14~P16 각 2건), 정답의 `click` 필드와 채점기 지원. 채점기 자기 검증 S2·S4 통과
