## 결과 (2026-10-14)

- 구조: `app/data/ui.html` 하나가 앱 화면(R1·R2)과 결과·보고서(R3~R20)를 함께 그린다. 보고서는 같은 파일의 `<script type="application/json" id="data">`에 결과 JSON을 넣은 단일 HTML(`<`는 `\u003c`로 이스케이프, 렌더링은 `createElement`+텍스트 노드만). 화면은 `state()`를 0.5초마다 읽는 폴링이라 pywebview와 예비 서버가 같은 코드를 쓴다
- `app/report.py`: result.json을 쓴 **뒤에** 돈다(검출 시간 밖). 묶음·위험도·원인 유형·최초 발견일(`history.json`)·숨김 드러내기 캡처·`report.html`·`result.csv`(UTF-8 BOM)
  - 지문 = sha1(기법 + 공백 정리한 원문) 앞 10자리. R11·R18은 이 지문으로 확장
  - 원인 유형(R14): 같은 지문이 **2개 이상 페이지의 같은 location**에 있으면 해킹 삽입 의심. 목록·상세처럼 위치가 다르면 게시물형 (목록 미리보기 때문에 URL 수만으로 판정하지 않음)
  - 위험도: 심각 = 해킹 삽입 의심, 위험 = 숨김(OFFSCREEN·TRANSPARENT), 참고 = 보이는 변형(HOMOGLYPH·JAMO). 정렬은 위험도 → 영향 페이지 수 → 최초 발견일
  - R5 한 줄 요약은 규칙 신호로 만든 템플릿(토큰 0). 변형 글자는 코드포인트·유니코드 이름 표, 정규화 결과, 키워드, 계산된 스타일(detect가 `STYLE_JS`로 수집), HTML 조각, 선택자 복사
  - R6: 페이지를 다시 열어 숨김 요소에서 위로 올라가 240×80 이상인 보이는 부모 영역을 찾고, 숨김 사이 요소만 CSS로 풀어 전/후 2장(JPEG 60). 보이는 변형 광고는 테두리만. iframe은 프레임 URL로, src 없는·srcdoc iframe은 `content_frame`으로 찾는다. 작성자 칸(`writer`·`author`·`nick` 클래스)은 mask. 상한 100묶음·240초, 실패 시 새 탭으로 1회 재시도

## 시각 자료 보강 (2026-10-14)

- 근거 상세 맨 위에 시각 자료를 둔다: 숨김 해제 전후 비교 막대(열면 자동으로 한 번 쓸고, 인쇄하면 두 장 나란히) → 페이지 전체에서의 위치 → 발견 경로
- 재현 영상(Playwright 녹화, 심각 우선 최대 5개)은 만들었다가 뺐다: 전후 비교 막대·전체 위치·발견 경로가 같은 내용을 보여 주고, 일부 건에만 영상이 있어 사용자가 혼란스럽고, 보고서 +2.7MB·+1분·ffmpeg 동봉 부담이 있었다
- 페이지 전체 캡처: 주소마다 1장, device_scale_factor 0.5 컨텍스트에서 위 6000px까지. 광고 위치는 그림에 굽지 않고 좌표(`shot.pos`)로 저장해 화면에서 상자를 그린다
- 발견 경로: 크롤러 `via`(URL → 찾은 페이지, 방법)로 시작 주소부터의 경로를 만든다. 방법은 링크·sitemap·robots.txt·클릭(함수명)·더보기 클릭·스크립트 속 주소·새 창. 메뉴 링크가 아닌 방법은 노란 꼬리표
- 사이트 지도: 방문한 전체 페이지를 주소 경로로 묶은 나무, 검출 있는 페이지는 빨간 점, 검출 없는 페이지는 5쪽이 넘으면 접음. 위에 찾은 방법별 쪽수
- 확인: S1·S2·S4·S5 채점 100점 유지. 보고서 크기 S2 2.4MB(전체 캡처 0.6MB·부분 캡처 1.7MB), 보고서 단계 포함 전체 약 1분 30초
